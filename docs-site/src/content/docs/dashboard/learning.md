러닝 센터는 **AI가 현장 데이터로 스스로 배운 것**과 **그 예측이 실제로 얼마나 맞는지(자기 채점)** 를 보여주는 페이지입니다. 모델 5개가 각각 카드 하나입니다.

:::tip[먼저 큰 그림 — 4가지만 알면 됩니다]
1. **학습(배우기)** = 같은 일을 **많이 보면 보통값(중앙값)** 을 알게 됨. 데이터가 쌓일수록 똑똑해짐.
2. **예측** = 한 숫자가 아니라 **범위(분포)**. "보통 5분, 빠르면 1분, 늦으면 14분" 처럼.
3. **정답(ground truth)** = 실제로 일어난 일. 우리는 **트럭 GPS**를 1순위 정답으로 씀(아래 §정답).
4. **테스트** = 예측 vs 정답을 비교해 "얼마나 틀렸나"를 점수로. (MAPE·±30% 적중·재현율 등)
:::

## 0. 공통 개념 (모든 카드에 나옵니다)

### 카드는 두 부분 — 📈 학습 추이 / 🧪 최신 테스트
| 부분 | 무엇 | 비유 |
|---|---|---|
| **📈 학습 추이** | 시간이 갈수록 모델이 좋아지는지(쌓인 양·품질의 흐름) | 공부 시간이 쌓이는 그래프 |
| **🧪 최신 테스트** | 예측이 실제와 얼마나 맞나(채점 결과) | 모의고사 점수 |

### 추세 배지 (↑ 개선 / → 안정 / ↓ 악화)
처음값과 최근값을 비교해 좋아지는 방향이면 🟢개선, 거의 그대로면 → 안정, 나빠지면 🔴악화.

### 테스트 점수 용어 (쉽게)
| 용어 | 쉬운 뜻 | 좋은 방향 |
|---|---|---|
| **MAPE** | 예측이 실제와 **평균 몇 % 빗나갔나** | 낮을수록 ↑ |
| **±30% 적중률** | 예측의 ±30% 안에 실제가 들어온 비율 | 높을수록 ↑ |
| **재현율(recall)** | 실제로 일어난 일 중 **우리가 미리 맞춘 비율** | 높을수록 ↑ |
| **정밀도(precision)** | 우리가 "일어난다"고 한 것 중 **진짜 일어난 비율** | 높을수록 ↑ |
| **리드(lead)** | 예측 시점에서 실제까지 **남은 시간** | 클수록 일찍 알려줌 |
| **p10 ~ p90** | 빠른 편(하위 10%) ~ 늦은 편(상위 10%) 범위 | 분포의 폭 |

### 정답(ground truth)은 무엇으로 보나 — **GPS 우선**
"트럭이 실제로 언제 비었나"를 알아야 채점할 수 있습니다. 우리는 **트럭 자신의 GPS 사이클**(`tt_cycle_v2.dropped_at` = 트럭이 짐을 내린 순간)을 1순위 정답으로 씁니다. GPS가 빈 곳만 TOS 기록으로 보충합니다.

:::note[왜 GPS가 1순위가 됐나 — 실화]
처음엔 TOS의 "작업 완료" 시각(`comp_ts`)을 정답으로 썼는데, 적하(LD)에서 트럭이 비고 **~8분 뒤에** 찍히는 행정 기록이었습니다(완료=컨테이너가 배에 실린 시각). 그래서 "곧유휴 후 12분 뒤 빔"처럼 부풀려졌죠. 트럭 GPS로 교차검증하니 **진짜 빈 시각과 0.5분 차이**로 일치 → GPS를 1순위 정답으로 바꿨습니다. (양하 DS는 TOS 완료가 마침 GPS와 거의 같아 그대로 사용.)
:::

## 카드 ① — TT 이동시간 (한 trip이 몇 초 걸리나)

| 질문 | 답 |
|---|---|
| **무엇을 학습?** | 출발지→도착지(OD) 한 번 이동에 걸리는 시간 |
| **어떻게 학습?** | 완료된 GPS 사이클에서 trip을 5분마다 수확해 `learn_travel_sample`에 누적(+경로거리·혼잡밀도·날씨 피처도 자동 결합) |
| **예측 원리** | 그 OD의 **과거 시간들의 중앙값**(데이터 많으면 경험 분포 p10/p50/p90, 적으면 거리÷속도로 추정) |
| **테스트 방법** | 최근 trip의 실제 시간 vs 그 OD 중앙값 → MAPE·±30% 적중 |
| **결과 해석** | 현재 예시: **MAPE ~33% · ±30% 적중 ~46% · 중앙오차 ~3.8분**. 표본·신뢰 OD쌍이 늘수록 커버리지 ↑ |

:::caution[왜 더 못 맞히나 — 분포로 써야 함]
같은 출발→도착이라도 실제 시간은 **±50% 흩어집니다**(같은 길도 56초~37분). 그 순간 교통·양보·크레인 줄 때문이라 **결정 시점엔 알 수 없는 미래**입니다. 그래서 점 하나로 못 맞히고 **분포(보통+범위)** 로 씁니다.
:::

## 카드 ② — 작업지점 좌표 (블록·크레인이 정확히 어디?)

| 질문 | 답 |
|---|---|
| **무엇을 학습?** | 각 블록/크레인의 **정확한 위치(중심 좌표)** |
| **어떻게 학습?** | 트럭이 그 작업점에 ARRIVED했을 때의 GPS를 계속 모아 평균(중심점). 많이 모일수록 점이 또렷해짐 |
| **예측 원리** | 모아진 GPS의 중심 = 그 작업점의 좌표 |
| **테스트 방법** | 새 GPS가 학습 좌표에서 얼마나 떨어졌나(**잔차 = 위치 오차 ±m**) |
| **결과 해석** | 📈 = 잘 학습된 점 수(`n≥30` 확신 지점)가 늘어남. 🧪 = 위치 정밀도(±m)가 **작을수록** 정확. 라이브맵에서 신뢰도 색(🟢🟠🔴)으로 확인 |

> 비유: 친구가 매번 "여기서 만나"라고 한 자리들을 점으로 찍다 보면, 점들이 모여 **진짜 약속 장소**가 또렷해지는 것과 같아요.

## 카드 ③ — 주행 차선 (트럭이 어느 길로, 어느 방향으로 다니나)

| 질문 | 답 |
|---|---|
| **무엇을 학습?** | 트럭이 실제로 다니는 **길(도로 셀)과 방향** |
| **어떻게 학습?** | 움직이는 트럭의 GPS 자취를 22m 격자에 모아 셀마다 통과 수·방향·평속 누적 |
| **예측 원리** | 통과가 충분한 셀(≥20) = "도로". 방향이 한쪽으로 쏠리면 일방통행 |
| **테스트 방법** | 학습한 방향이 실제 트럭 흐름과 맞는지(방향 일관성 = 일방 비율) |
| **결과 해석** | 📈 = 학습된 도로 셀 수가 늘수록 지도 완성. 🧪 = 일방 비율↑ = 방향이 또렷. 라이브맵에서 **화살표**로 표시 |

## 카드 ④ — Soon-idle 예측 (트럭이 곧 비나? 몇 분 뒤에?)

이 카드는 두 가지를 합니다: **(a) 곧 빌지(예/아니오)** 와 **(b) 몇 분 뒤에 빌지**.

| 질문 | 답 |
|---|---|
| **무엇을 학습?** | 트럭이 곧 유휴가 되는 순간 + 그때까지 남은 시간(리드) |
| **어떻게 학습?** | 매 30초 soon_idle 예측을 기록(`tt_soon_idle_pred`) → 나중에 실제 빈 시각(**GPS 정답**)과 맞춰봄 |
| **예측 원리** | 작업유형별 **학습된 중앙 리드**(DS/LD 각각) |
| **테스트 방법** | 예측 vs 실제(GPS-우선 정답): 재현율·정밀도·리드(p10~p90)·분 예측 MAPE |
| **결과 해석(예시)** | **리드: DS ~5분 / LD ~3.2분 뒤 빔**. 정밀도 DS 92~93% / LD 72%. 재현율 DS ~46% / LD ~66%. 분 예측 MAPE DS ~58% / LD ~66% |

### 📈 학습 추이 (위) — DS·LD 재현율 흐름
시간이 갈수록 "실제로 빈 트럭을 우리가 미리 맞춘 비율(재현율)"이 어떻게 변하는지.

### 🧪 최신 테스트 (아래) — 리드타임 카드 (DS / LD)
- 큰 숫자 = **예측: N분 후 유휴(중앙)**, 막대 = p10~p90 범위, 적중 수.
- 🎯 분 예측 정확도 = MAPE · ±30% 적중.
- 재현율 옆 `(GPS 39→TOS +Δ%p)` = GPS 신호만으로는 놓쳤을 것을 **TOS 보정 신호가 얼마나 더 잡았나**(순이득).

:::note[정밀도가 LD에서 더 정직해진 이유]
TOS 라벨만 쓸 땐 LD 정밀도가 40%로 낮게 나왔는데, 이는 TOS가 놓친 실제 빔을 "헛발화"로 잘못 센 탓이었습니다. **GPS-우선 정답**으로 바꾸니 72%로 — 진짜 정밀도가 드러났습니다.
:::

## 카드 ⑤ — 유휴 분 예측: 피처로 더 맞출 수 있나 (DS·LD)

④의 "몇 분 후 유휴"를 **추가 정보(피처)로 더 정밀하게** 맞춰보려는 시도입니다. 두 작업을 한 카드에 묶었습니다.

| | DS (양하) | LD (적하) |
|---|---|---|
| **피처(단서)** | RTG까지 거리 × 발화 신호 | 없음(안벽이라 거리=없음·신호 고정) |
| **예측** | 거리 구간별 중앙(≤30m 4분 → >150m 6.7분) | 학습 중앙값(~3.2분) |
| **테스트(MAPE)** | ~57% (평균 58% 대비) | ~66% |

### 어떻게 테스트했나 — 홀드아웃(공정 채점)
같은 데이터로 배우고 같은 데이터로 채점하면 "컨닝"입니다. 그래서 **반은 학습, 반은 시험**으로 나눠(짝수/홀수) 공정하게 채점했습니다.

### 결과 해석 — 정직한 결론
- **DS**: 거리는 *중앙 예측*을 밀어주지만(가까우면 빨리 빔), **per-건 오차는 거의 안 줄어듦**(58→57%).
- **LD**: QC·시간대·큐를 다 시험했지만 전부 그냥 평균과 같음(~65%) → **쓸 만한 피처 없음**.
- 공통 원인: **크레인 줄(큐)이 언제 내 차례가 될지는 미리 알 수 없는 확률**이라 천장이 있습니다.

:::tip[그래서 결론]
유휴 분 예측도 **점 하나가 아니라 분포(p10~p90)** 로 쓰는 게 맞습니다. 더 정밀히 하려면 거리·신호가 아니라 **RTG 큐 깊이/작업률 같은 동적 정보**가 필요합니다(현재 미보유).
:::

## 한눈 정리표 (5개 모델)

| 카드 | 무엇을 학습 | 정답(테스트 기준) | 핵심 점수(예시) | 천장 이유 |
|---|---|---|---|---|
| ① 이동시간 | OD trip 시간 | 실제 trip 시간 | MAPE 33% | 순간 교통(±50%) |
| ② 작업점 좌표 | 블록·크레인 위치 | 새 GPS 잔차 | 정밀도 ±m↓ | (수렴하면 안정) |
| ③ 주행 차선 | 길·방향 | 실제 흐름 | 도로셀↑·일방%↑ | — |
| ④ 곧유휴 | 곧 빔 + 몇 분 후 | **GPS 빔(dropped_at)** | 리드 DS5·LD3.2분 | 큐 확률성 |
| ⑤ 유휴 분(피처) | 분 예측 정밀화 | GPS 빔 | DS 57·LD 66% MAPE | 큐 확률성 |

:::caution[숫자는 "현재 예시"입니다]
위 점수들은 데이터가 쌓이며 바뀝니다. **방법(어떻게 배우고 채점하나)** 은 고정이고, **숫자**는 페이지에서 실시간으로 갱신됩니다. 화면 값이 이 문서와 다르면 화면이 최신입니다(그리고 이 문서를 업데이트하세요).
:::
