2단계 배차 로직([설계](/kc/dispatch/)) 구현을 위한 **조사 과정·결과**를 시간순으로 누적합니다. 새 발견·결정이 생길 때마다 맨 위에 날짜 항목을 추가합니다.

:::note[작성 규칙]
- 항목은 **최신이 위로**. 날짜는 KST.
- 각 항목: **무엇을 조사했나 → 발견(데이터/수치) → 결정·다음 할 일**.
- 추정은 사실과 구분해 표기. 관측 못 한 값은 "미상".
:::

## 2026-06-18 — 착수 · 로직 정의 · 빌딩블록 감사

**로직 확정(개념).** 사용자와 2단계 배차로 합의:
- **1단계(수요, 위치 무관):** 작업별 데드라인(선박 출항 ÷ QC 남은 큐) vs 차량 도달 통상시간 → QC별 "지금 차량 붙어야 할 작업" 결정.
- **2단계(공급, 위치 고려):** 후보 작업×후보 차량 비용행렬(도달 예측시간) → 최적 매칭 → 최종 배차.
- 근거: 비자동화 터미널이라 데이터 품질·예측 정확도가 낮음 → 데드라인 결정과 위치 매칭을 분리(예측 오차가 데드라인 결정을 오염시키지 않게).

**빌딩블록 감사(코드/DB 확인):**
- ✅ **OD 이동시간 모델** — `learn_travel_sample` / `learn_travel_metric` (origin/dest zone, travel_s). 2단계 비용행렬의 도달시간 예측에 사용.
- ✅ **QC 남은 작업 큐** — `live_workqueue`(qc·vessel·queuename·seq·total_qty·comp_qty), `live_workpool`(컨테이너·ytno·etw·actv). 1단계 데드라인 분배 대상.
- ✅ **ETW(작업예정시각)** — `tos_etw_cntr` + `live_workpool.etw_ts`(TOS ETW RPC).
- ✅ **위치** — QC: 학습 centroid(`learn_topos_point`, is_crane) + 크레인 GPS / 차량: `wpt_gps`(라이브).
- ❌ **선박 출항(ETD)/마감 시각 — 미적재.** `VSS_STATISTICS`(c06_k_mph_voyage.sql)엔 `VSS_STT_ABERTHTIME`(berth 작업시간, 분 단위 *기간*)·moves·teu 등 통계만 있고 **출항 타임스탬프가 없음**. `voyage_plan.sql`도 planned_moves만.

**결정·다음 할 일:**
- 🎯 **선행 과제 = ETD 데이터 소스 발굴(Q5).** TOS에서 선박 스케줄(ETB/ETD/cut-off)이 든 테이블을 데이터딕셔너리로 조사 → 적재 파이프라인 설계. (toolbox 저부하 직접조회, 직렬·인덱스세이프.)
- Q1~Q4는 사용자 입력 대기.
