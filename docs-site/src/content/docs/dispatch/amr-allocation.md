> 목적: OPUS 터미널 운영시스템(TOS)이 **실제로** 어떻게 ① 작업 우선순위를 정하고 ② 안벽
> 크레인과 운반차량을 맞물리고 ③ 야드 블록을 배정하는지 데이터로 분석한 결과를 정리하고,
> 거기서 **자율주행 운반차량(AMR)에 일을 나눠줄 때의 요구사항과 우선순위 기준**을 도출한다.
> 마지막으로 우리가 만든 **2단계 배차 로직**이 이 요구사항을 어떻게 충족하는지 설명한다.
>
> ※ 이 단지는 자동화 터미널이 아니라 사람이 운전하는 트럭으로 운영된다. 따라서 본 분석은
> "현행 OPUS 운영을 그대로 AMR로 대체할 때 무엇이 필요한가"를 도출하는 데 초점이 있다.

---

## 1. OPUS 터미널 운영 로직 (실측 분석)

### 1.1 작업 우선순위 체계 — 모든 우선순위는 "선박 출항"에서 나온다
- 모든 작업은 결국 **선박 일정**에 종속된다. 각 선박은 **출항 예정시각(ETD)** 을 가지며, 그
  전에 **양하**(배에서 내릴 컨테이너)와 **적하**(배에 실을 컨테이너)를 모두 끝내야 한다.
- 작업의 최소 단위 = **컨테이너 한 개의 이동(move)**. OPUS의 작업주문 목록에서 각 컨테이너는
  상태로 관리된다: **계획 → 대기 → 진행 → 완료**(P/Q/A/C). "대기"는 아직 트럭이 안 붙은
  실수요, "진행"은 트럭이 배정돼 처리 중인 건이다.
- 각 컨테이너에는 **예정 작업시각(ETW)** 이 매겨진다 = 크레인이 그 컨테이너를 처리할 대략의
  시점. 작업들은 **선박별 큐(베이 단위)** 로 묶이고 **순서(시퀀스)** 가 있으며, **갑판/선창**,
  **양하/적하** 로 구분된다.
- **우선순위의 본질**: "출항이 임박한 선박" × "크레인이 곧 도달할 작업"이 가장 급하다. 출항이
  멀면 같은 작업도 급하지 않다(나중에 해도 됨).

### 1.2 크레인 연동 타이밍 — 본 시스템의 심장
안벽 크레인(QC)은 컨테이너를 **한 개씩 순서대로** 처리한다. 운반차량은 그 리듬 사이를 메워야
한다.

- **양하**: 크레인이 배에서 내려 트럭에 적재 → 트럭이 야드로 운반 → 블록에 하차.
- **적하**: 트럭이 야드 블록에서 컨테이너 픽업 → 크레인 밑으로 운반 → 크레인이 배에 적재.
- **크레인 굶주림(starvation)**: 크레인이 다음 컨테이너를 작업하려는데 트럭이 없어서 멈추는 것.
  안벽 생산성 = 선박 체류시간이므로 **이것이 가장 큰 손실**이다. AMR 배분의 1차 목표는 "크레인을
  굶기지 않는 것"이다.

크레인이 **N번째 컨테이너에 도달하는 시각**은 다음 요소로 예측 가능하다(모두 실측 기반):

| 요소 | 실측값 | 의미 |
|---|---|---|
| 무브 1개 시간 | 양하 ~90초 / 적하 ~110초 | 크레인별·작업별 다름(같은 작업도 크레인 따라 79~128초, ~45% 차이) |
| 트윈 리프트 | 남은 작업의 ~25% | 한 번에 2개 → 무브 수가 컨테이너 수보다 적음 |
| 베이 변경 | ~3분 | 크레인이 다른 베이로 이동(갠트리) |
| 해치커버 | 양하 ~7분 / 적하 ~8분 | 갑판↔선창 전환 시 덮개 작업 |

→ 이 모델로 "크레인이 각 컨테이너에 도달하는 시각"을 계산하고, **트럭은 그 시각보다 먼저
도착**해야 한다.

- **리드타임(트럭을 미리 보내야 하는 시간, 실측)**: **양하 ~5분**(빈 트럭이 크레인으로 가는
  시간), **적하 ~20분**(블록을 들러 컨테이너를 집어오는 왕복 전체). 양하·적하가 **약 4배** 차이
  나므로 작업 유형별로 다르게 다뤄야 한다.

### 1.3 야드 블록 배정 규칙
- **양하**: 목적지 = 배정된 **야드 블록**. 트럭이 크레인→블록으로 운반.
- **적하**: 출발지 = 지정된 **야드 블록(픽업 위치)**. 트럭이 블록→크레인으로 운반.
- 블록에는 **야드 크레인(RTG)** 이 있어 트럭과 핸드오버한다. 트럭-RTG 타이밍도 대기에 영향.
- **위치(존/블록/베이)별 이동시간이 다르다**. 어느 트럭이 어느 작업에 가까운지가 효율을 좌우 →
  "위치 인지 매칭"이 필요한 근거.

## 2. AMR 작업 배분 요구사항 (위 분석에서 도출)

| # | 요구사항 | 근거(1장) |
|---|---|---|
| **R1** | **데드라인 인지** — 각 작업의 "크레인이 필요한 시각"을 알아야 함(선박 ETD에서 크레인 잔여작업 역산) | 1.1, 1.2 |
| **R2** | **이동시간 보정** — AMR이 제때 도착하도록 OD 이동시간만큼 미리 출발 지시 | 1.2 리드타임, 1.3 |
| **R3** | **양하/적하 구분** — 적하는 블록 왕복이라 리드타임이 훨씬 김(~4배) | 1.2 |
| **R4** | **과·과소 배차 회피** — 너무 일찍 = AMR 대기 낭비, 너무 늦게 = 크레인 굶주림 | 1.2 |
| **R5** | **위치 인지 매칭** — 어느 AMR을 어느 작업에 → 전체 도착시간 최소화 | 1.3 |
| **R6** | **불확실성 견딤** — 비자동화 터미널이라 데이터·예측이 부정확 → 부정확에 덜 휘둘리는 구조 | 전반 |

## 3. AMR 작업 우선순위 기준

1. **데드라인 긴급도** — 선박 출항 / 크레인 도달까지 남은 여유가 적을수록 우선.
2. **크레인 굶주림 위험** — 곧 일이 떨어지는 크레인에 가는 작업을 우선.
3. **이동 실현성** — 제때 도착 가능한가. 불가능하면 그 작업엔 **더 가까운 AMR**을 배정.
4. **전체 비용 최소화** — 개별이 아니라 **시스템 전체**의 도착시간/유휴를 최소화.

> 핵심 원칙: **"굶주림을 막는 것"(2)이 "차량 효율"(4)보다 우선**하되, 같은 조건이면 전체 비용이
> 낮은 매칭을 택한다.

---

## 4. 우리 배차 로직 (2단계) — 요구사항·우선순위를 어떻게 구현하나

데이터·예측이 부정확한 비자동화 터미널이므로, **"무엇을 해야 하나(수요)"** 와 **"누구를
보낼까(공급)"** 를 분리한다.

### 4.1 1단계 — 수요 결정 (위치 무관) → R1·R3·R4 / 우선순위 1·2
- 크레인별 잔여 작업을 **타이밍 모델(1.2)** 로 계산해 각 컨테이너의 **작업-ETA**(크레인이 도달할
  시각)를 구한다.
- 선박 **ETD에서 역산** → **배차 마감 = 작업-ETA − 리드타임** = "이때까지는 AMR을 보내야
  한다."
- 출력 = **"지금 AMR이 붙어야 할 작업 목록"**. 이 단계는 **후보 차량 위치를 보지 않는다** →
  부정확한 위치 예측에 데드라인 판단이 휘둘리지 않게(R6).

### 4.2 2단계 — 최적 매칭 (위치 고려) → R2·R5 / 우선순위 3·4
- 1단계 후보 작업 × 후보 AMR(**유휴 + 곧 유휴**)을 **OD 이동시간 비용행렬**로 매칭(할당 문제)
  → 최적 배차.
- 위치 예측은 **상대 비교**에만 쓰이므로 절대 오차의 영향이 작다(R6).

> 즉, **1단계가 우선순위(데드라인·굶주림)** 를 결정하고, **2단계가 그 우선순위를 지키는 최소비용
> 매칭**을 찾는다.

## 5. 검증 — 실제로 맞는지 어떻게 확인하나

- **예측 정확도(그림자 로깅)**: 작업-ETA/배차 마감 예측을 **실제 작업시각**과 대조. (현재: 양하
  오차 중앙 ~3분으로 평균적으로 calibrated, 개별은 노이즈 큼 → 크레인 단위 신호로는 충분.)
- **인과 검증(진행 중)**: 크레인 굶주림 사례에서 **"TOS 실제 배차시각 vs 우리 권고 마감"** 을
  비교하고, **이동시간을 통제**해 *"우리가 더 일찍 보냈으면 막았을"* 사례와 *"트럭이 멀어 어차피
  못 막았을"* 사례를 구분한다. 거시 지표로 **출항 데드라인 미스**도 본다.

---

## 6. 가정·한계 (정직하게)

- 비자동화 운영이라 일부 신호가 부정확하다: 작업 큐의 컨테이너 단위 순서, TOS의 실제 배차 시각
  등 → "블록/베이 단위", "시각 근사"로 보수적으로 다룬다.
- 선박 **작업완료예정** 값이 낡아(stale) 신뢰 불가 → 마감은 **출항 예정(ETD)** 으로 역산.
- 1단계 예측은 평균은 맞지만 개별 컨테이너 타이밍은 거칠다 → 컨테이너 1개가 아니라 **크레인
  단위 수요 신호**로 활용.

### 부록: 용어
- **QC**(안벽 크레인): 배에서 컨테이너를 내리고/싣는 크레인. **RTG**(야드 크레인): 야드 블록에서
  트럭과 핸드오버하는 크레인.
- **양하(DS)** 배→야드 / **적하(LD)** 야드→배.
- **ETD** 출항 예정시각 · **ETW** 컨테이너별 예정 작업시각 · **OD** 출발지-도착지(이동시간).
- **AMR** 자율주행 운반차량(현행 유인 트럭을 대체).
