**상태:** `설계 확정 · 데이터 수집 중` · **최종 검토:** 2026-06-17

이 문서는 **TT(야드 트럭)의 한 번 이동(trip)이 몇 초 걸릴지 예측하는 모델**의 입력·출력·학습 방법을 정리합니다. 배차가 "이 트럭을 저 작업에 보내면 언제 도착하나"를 알아야 해서 만듭니다. 처음 보셔도 이해되도록 천천히 씁니다.

## 한눈 요약

1. **trip = 한 번의 연속 이동** (출발지에서 *움직이기 시작* → 목적지에 *도달*). 적재·공차 무관.
2. **출력은 "한 숫자"가 아니라 "분포"** (보통 N초, 빠르면 ~, 늦으면 ~). 같은 경로도 실제로 ±50% 흩어지기 때문(야드는 확률 시스템).
3. **입력은 두 부류:** ㉠ *어디서 어디로*(경로거리 — 순위는 됨) ㉡ *그 순간 상태*(혼잡 밀도·날씨 — ±50% 변동 공략 중).
4. **학습은 단순·누적식:** 화려한 ML이 아니라 OD별 경험분포 + 거리→시간 관계. 데이터가 쌓일수록 좋아짐.

## 1. 이 모델이 푸는 문제

배차 결정엔 세 입력이 필요합니다 — **①차량 작업 완료 시점, ②완료 지점, ③완료지점→후보까지 이동시간.** 이 문서는 **③ 이동시간**을 다룹니다([①②는 곧유휴 연구](/kc/research/soon-idle-tos/) 참고).

## 2. trip이란? (모델의 단위)

```
빈다 ─[① 유휴: 배차 대기]─[② 공차 주행]─[③ 픽업 대기+적재]─ 찬다 ─[④ 적재 주행]─[⑤ 드롭 대기+하역]─ 빈다 …
                          └──── trip ────┘                      └──── trip ────┘
```

**trip = 출발지에서 *움직이기 시작한 순간* → 목적지에 *도달한 순간*** (순수 주행). 적재 여부 무관.
- 경계는 **모션 이벤트**(출발/도착)지 핸드오버(적재/하역)가 **아님** → 유휴·크레인 대기는 trip에 안 들어감.
- 컨테이너 작업 1건 = **2 trip**(공차 trip + 적재 trip).
- 데이터 출처: GPS 사이클 추적기(`tt_cycle_v2`)의 레그 `left`(출발 모션)→`arrived`(도착 모션). 이건 핸드오버가 아니라 **속도 기반 모션 경계**라 trip 정의와 맞습니다.

## 3. 출력 — 왜 "분포"인가 ⭐

가장 중요한 설계 결정입니다.

> **출력 = 한 숫자(❌ "350초")가 아니라 분포(✅ "보통 350초 · 빠르면 200 · 늦으면 700").**

**근거(측정):** 같은 OD(동일 출발→도착)인데도 실제 시간이 **쌍내 변동계수 0.50, p90/p10 약 5배** 흩어집니다. 같은 블록→같은 QC가 **56초 만에 끝나기도, 37분 걸리기도** 합니다.

**왜?** 이 변동은 모델이 부족해서가 아니라 **야드가 확률 시스템**이라서입니다 — 순간 교통·양보·경로 차이·크레인 큐. **결정 시점엔 관측 불가능한 미래 상태**라 점 하나로 맞추는 건 원천적으로 천장이 낮습니다. 그래서 정직한 출력은 **기댓값 + 불확실폭**입니다.

## 4. 입력 설계 ⭐

### 철칙: "결정 시점에 아는 것"만 입력
trip 시작 *전*에 배차하므로, 그때 모르는 건 못 씁니다.
- ❌ **실제로 달린 경로/거리** — trip이 끝나야 아는 사후정보(넣으면 컨닝). 대신 **"그 OD에서 보통 얼마나 도는지"의 학습값**을 씀.

### ㉠ "어디서 어디로" — OD 간 차이 (순위 결정, *됨*)
| 입력 | 정체 | 신호 |
|---|---|---|
| **기대 경로거리** | 그 OD의 *과거 실주행거리 중앙값* | **corr 0.39** (주 신호) |
| 출발/도착 존 | 블록+베이 · 안벽 50m GPS격자 | 거리·그룹 키 |
| 적재/공차 | 속도 다름(공차 6.6 · 적재 7.3 km/h) | 보정 |

> **왜 직선거리가 아니라 경로거리?** 직선거리는 차선을 무시해 약했습니다(corr 0.29). 실제 주행거리는 **2배 잘 설명**(0.60). 예측엔 미래 경로를 모르니 *OD별 주행거리 중앙값*(경로거리, corr 0.39)을 씀. 근/원 분리 1.96배 → 2.21배로 또렷해짐.

### ㉡ "그 순간의 상태" — OD 내부 변동(±50%) 공략 (*수집 중*)
같은 OD가 흩어지는 그 변동. 실제 교통·날씨라, **그 순간 공간 상태**만이 설명 가능.
| 입력 | 정체 | 상태 |
|---|---|---|
| **존별 차량 밀도** | 경로 회랑의 셀별 트럭 수(50/100/150/200m 4종 동시 수집) | 🔄 수집 중 — within-OD 최선의 한 방 |
| **날씨(스콜)** | 1분 강수·시정(Tomorrow.io) | 🔄 수집 중 — 드문 대형 타격 |
| 시간대(dow/hour) | — | 약함, 보조 |

### 버린/약한 입력 (왜)
- ❌ **직선거리** → 경로거리로 대체.
- ❌ **전역 혼잡도**(동시 in-flight 수, corr −0.14) — 공간정보 없어 무의미 → 존별 밀도로 대체.
- ❌ **시간별 날씨** — 20분 스콜이 1시간 평균에 희석 → 1분으로 대체.

## 5. 출력 만드는 법 — 3단 폴백

데이터 조밀도에 따라:
1. **OD 충분히 쌓임** → 그 OD의 **경험 분포**(과거 시간들의 p10/p50/p90)를 그대로.
2. **드묾(대부분)** → **경로거리 모델**로 p50 + **전역 분산(±50%)** 로 p10/p90.
3. **처음 보는 OD** → 직선거리 × detour계수(~1.2)로 경로거리 추정 후 2번.

→ 조밀한 곳은 실측 분포로 정밀하게, 희소한 곳은 거리로 거칠게, **항상 분포를 냄.**

## 6. 학습 방법

- **라벨(정답)** = 실제 trip 시간(모션 출발→도착, 정밀 도착만, 10초~1시간으로 클린).
- **누적식 온라인 학습:** 애그리게이터가 5분마다 완료된 GPS 사이클에서 trip을 수확해 `learn_travel_sample`에 적재. **데이터가 쌓일수록 OD 커버리지·셀 밀도가 늘어 정확해짐.**
- **모델 형태 = 단순 룩업 + 회귀** (복잡한 ML 불필요). 신호가 약해서(corr 0.39) 화려한 모델을 써도 **뽑을 신호가 없어** 더 못 맞춤. 대신 해석·디버깅이 쉬움.
- **피처 자동 수집:** 경로거리(주행레그) · 밀도(`zone_density` 60초 스냅샷) · 날씨(`weather_1min`) · 시간 — 전부 백그라운드로 모여 trip에 자동 결합됨.

## 7. 데이터 파이프라인

```
GPS 사이클(tt_cycle_v2) ──5분──▶ trip 수확 ──▶ learn_travel_sample (origin/dest/travel_s)
존별 밀도(zone_density, 60초·4격자) ──┐
날씨(weather_1min, Tomorrow.io 1분) ─┼─▶ trip 시각·경로로 결합 ──▶ 같은 테이블의 피처 컬럼
주행거리(tt_cycle_log) ──────────────┘                              (density_*·trip_ts 등)
```

| 테이블 | 내용 | 주기 |
|---|---|---|
| `learn_travel_sample` | trip 1건/행 + 피처 + 라벨 | 5분 적재 |
| `zone_density` | 셀별 TT 수(50/100/150/200m) | 60초 |
| `weather_1min` | 1분 강수·시정·풍속 | 3분 폴링 |
| `tt_cycle_log` | 사이클 주행거리·시간 | 실시간 |

## 8. 현재 상태와 정직한 발견 (수치)

| 항목 | 결과 |
|---|---|
| 경로거리 ↔ 시간 | corr **0.39**(직선 0.29) — 순위 *됨*, 모더릿 |
| 같은 OD 쌍내 변동 | CV **0.50**, p90/p10 ≈ 5배 — 진짜 확률성 |
| 전역 혼잡도 | corr −0.14 — 무의미(폐기) |
| 날씨(시간별) | 무신호 → 1분으로 재시도 중 |
| 존별 밀도 | 수집 시작, 평가 대기 |

**중간 결론:** ③ 이동시간은 **거친·분포형 입력**입니다 — 정밀 점예측은 천장이 낮음. 배차는 **기댓값 + 폭**으로 쓰고, 정밀 경쟁 대신 **유휴 제거 + 가용성(곧유휴)** 같은 통제 가능한 레버에 집중. within-OD 변동을 밀도·날씨가 깰 수 있는지는 **데이터 쌓은 뒤 평가**가 판가름.

## 9. 배차에서 쓰는 법

- 후보들을 **p50(기대)로 순위** → 명백히 가까운 트럭 선택(분포 안 겹치면 확실, 비슷하면 무관).
- **폭(p10~p90)으로 리스크 관리** — 꽉 짜지 말고 슬랙, 자주 재평가(그리디/롤링).
- 점추정 정밀 최적화 **금지**(노이즈 바닥 밑은 환상).

## 10. 예시 한 건

> **입력:** `06T-12(블록) → C29(안벽), 공차`, 지금 14:30, 비 안 옴, 경로 혼잡 보통
> → 기대 경로거리 1,200m
> **출력:** **p50 350초 (p10 200 · p90 700)**
> **배차:** "이 트럭 약 6분(최대 12분) 후 도착" 으로 후보 비교에 사용.
