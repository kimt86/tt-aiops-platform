**상태:** `살아있는 문서` · **최종 검토:** 2026-07-13 · **현재 단계:** 그림자(계산·권고·검증만, 실제 차량 지시는 TOS)

:::caution[함께 다듬는 계획]
날짜가 아니라 **게이트(통과 기준)** 로 정의합니다. 실제 일정은 팀 역량과 조직 합의에 따라 정해집니다. 상태(✅ 완료 / 🔨 진행중 / ⬜ 미착수)는 현시점 기준입니다.
:::

## 한 줄 요지

모델과 배차 로직은 이미 라이브 그림자로 성숙하게 돌고 있습니다. **더 만들 모델이 남은 게 아니라**, 정식 전환의 관건은 네 가지입니다 — **① 권고를 내보내는 출력 채널, ② 우리가 더 낫다는 정량 증거, ③ 24/7 운영 견고성, ④ 단계적 파일럿.**

## 현재 위치

| 지표 | 값 | 의미 |
|---|---|---|
| 선박 데드라인 | **243척 적재** ✅ | 출항(ESTDEP)·완료(ESTWKC) 전부 — 1단계(마감 계산) 선행조건 해결 |
| 2단계 실현가능성 | **81.8%** | 마감 안에 도착하는 권고 비율(최근 24시간) |
| 최적 매칭 이득 | **−5.1%** | 최적 배정이 단순 그리디 대비 아낀 공차시간 |
| 이동시간 GBM | **+8pp** | 통계 중앙값 대비 MAPE 개선(그림자 검증 중) |
| 유휴시간(곧-빔) | 재설계 중 🔨 | "작업지점 도착 + 앞대수 × 크레인 사이클" 검증 중 |
| 가동 모델 | 4종 라이브 | 도로망·이동시간·작업지점·QC (배차 비용·목적지에 실사용) |

## 남은 작업 — 4개 워크스트림

유형: **[기술]** · **[조직]** · **[기술+조직]**

### A. 출력 · 통합 &nbsp;🔴 크리티컬 패스

지금 우리 권고는 내부 그림자 기록(배차 매칭 로그)에만 있습니다. "서비스"가 되려면 외부가 구독·소비할 채널과 계약이 필요합니다.

- ⬜ **A1 · 브로드캐스트 채널 구현** [기술] — 배차 권고를 외부 구독용 안정 API/피드로. 스키마·주기·재전송·인증.
- ⬜ **A2 · TOS/운영측 계약 합의** [기술+조직] — 무슨 필드를·얼마나 자주·어떤 의미로 넘기고, TOS가 이를 어떻게 소비할지. *(A1 선행 · 조직 합의 필요)*
- ⬜ **A3 · 신선도·지연 검토** [기술] — 현재 60초 주기가 실제 배차에 충분한지, 이벤트 기반 즉시 갱신 필요 여부.

### B. 신뢰 확보 (검증)

누구도 검증 안 된 권고에 트럭을 맡기지 않습니다. "우리가 낫다"를 합의된 방식으로 증명해야 합니다.

- 🔨 **B1 · 유휴시간 재설계 완주** [기술] — 후보 차량 풀 타이밍의 근거. 작업지점 도착 + 앞대수 모델, 검증 진행 중.
- 🔨 **B2 · 이동시간 GBM 그림자 → 배선** [기술] — 며칠 이기면 배차 경로에 서빙.
- ⬜ **B3 · "TOS보다 낫다"의 정량 증거** [기술+조직] — 수주간·시나리오별 공정비교. 현재 절감치는 "대부분 원거리 교정"이라 더 단단한 근거 필요. *("낫다"의 정의 합의 필요)*
- ⬜ **B4 · 실현불가 18% 규명** [기술] — 마감이 틀린 건지, 트럭이 진짜 먼 건지 분해.

### C. 운영 견고성

그림자는 실패해도 무해하지만, 서비스는 24/7 무인으로 버텨야 합니다. 대부분 미착수.

- ⬜ **C1 · 장애 대응·강등·폴백** [기술] — 웹소켓 끊김·추출기 정지·모델 이상값 시 우아한 강등과 안전한 폴백.
- ⬜ **C2 · 배차 파이프라인 모니터링·알림** [기술] — 지금은 KPI 대시보드뿐. 배차 자체의 헬스·지연·이상 감시.
- ⬜ **C3 · 프로덕션 하드닝** [기술] — 연구/그림자 코드베이스를 무인 운영 등급으로. 재시작 안전·자원·회귀 방지.

### D. 파일럿 · 조직 &nbsp;🔴 결정 필요

그림자에서 전면 제어로 바로 못 넘어갑니다. 단계적 롤아웃과 조직 합의가 필요합니다.

- ⬜ **D1 · 단계적 롤아웃 + 롤백 설계** [기술+조직] — 자문 → 부분 → 전면, 각 단계 진입/통과 기준과 롤백 절차. *(아래 로드맵)*
- ⬜ **D2 · 운영자 UI** [기술] — 휴먼인더루프 단계에서 권고를 보고 채택/무시할 화면.
- ⬜ **D3 · 수용기준·책임·교육** [조직] — 우리 배차가 틀렸을 때의 권한/책임, 운영자 교육, TOS팀 통합.

:::danger[크리티컬 패스]
**A1→A2(출력 채널 + 계약)** 와 **D1(파일럿 설계)** 가 병목이며, 둘 다 기술 외 **조직 합의**가 필요합니다. **B1(유휴시간)** 은 신뢰의 선행조건. 모델을 더 만드는 것보다 이 세 갈래가 정식 전환을 좌우합니다.
:::

## 단계적 롤아웃 — 날짜가 아니라 게이트로

각 단계는 통과 기준(게이트)을 만족해야 다음으로 넘어갑니다.

### Phase 0 · 그림자 (현재)
계산·권고·검증만. 실제 차량 지시는 TOS. 모든 모델·로직이 라이브로 돌며 실측과 대조됩니다.
> **통과 기준** — B1 유휴시간 재설계 검증 + B3 "TOS보다 낫다" 초기 증거 확보.

### Phase 1 · 자문 (Advisory)
운영자가 우리 권고를 **화면으로 봅니다** — 제어는 하지 않음. 실제 채택은 사람이 판단.
> **필요** — A1 출력 · D2 운영자 UI · C2 모니터링
> **통과 기준** — 운영자 수용 + 권고 신뢰(현장에서 "봐도 될 만하다") + 무중단 안정.

### Phase 2 · 부분 (Partial)
일부 **트럭/레인/교대에만** 우리 배차를 실제 적용. 나머지는 TOS. 범위를 좁혀 위험을 가둡니다.
> **필요** — A2 계약 · C1 폴백 · D1 롤백 · D3 책임
> **통과 기준** — 부분 범위에서 TOS 대비 개선 입증 · 무사고 · 폴백/롤백 실증.

### Phase 3 · 전면 (Full)
전 트럭을 우리 배차로. TOS는 **감독·예외 처리**. 정식 서비스.
> **전제** — Phase 2 지표 지속 + C3 프로덕션 하드닝 완료 + 조직 최종 승인.

## 위험 · 미결정

- **조직 합의가 최대 불확실성** — TOS팀 통합·책임 소재·수용 기준이 미정. 기술이 준비돼도 이게 없으면 Phase 1조차 못 넘습니다. → 조기 착수 권장.
- **"낫다"의 정의 미합의** — 공정비교 기준이 합의 안 되면 게이트 통과 판정이 불가능합니다. B3와 함께 지표 정의를 먼저 확정.
- **유휴시간이 안 풀리면 곧-가용 후보가 약함** — B1 재설계가 지연되면 2단계 후보 풀의 "곧 가용" 부분이 부정확 → 전 단계 신뢰에 영향.
- **일정 미확정** — 이 계획은 게이트로 정의됩니다. 실제 일정은 팀 역량과 조직 결정에 따라 정해집니다.
