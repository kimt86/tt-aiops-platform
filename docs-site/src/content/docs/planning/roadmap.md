## 한 것 (요약)

- 실시간 대시보드 + KPI 7종 + websocket 정확도 보강.
- `idle→staging` 분류 교정, 라이브 배차 풀.
- **작업 사이클 적재** — `tt_cycle_log`(v1) + `tt_cycle_v2` 그림자.
- **사이클 v2** — 6-이벤트 모델(핸드오버 수집 포기), 픽업 레그 보장, CYCLES 페이지에 6이벤트 노출. 상세 [실험](/kc/experiments/cycle-v2-shadow/).
- **공차 레그 분해** — `learn_leg_decomp`: 각 공차 레그의 **구간시간(`total_s`·출발→도달, 이동시간 라벨)** 과 그 안의 움직임(drive_s·~53%)/정지(stop_s·~47%) 분해를 진단용으로 저장. 핵심 발견: (a) ARRIVED ≈ 실제 도착(중앙값 −4초) → 큰 크레인 대기는 이동시간 **안이 아니라 ARRIVED 이후**, (b) 예전 표시하던 "중앙값 6.9km/h"는 직선÷정지포함시간÷짧은레그 가중 착시, (c) 같은 OD여도 크게 흩어짐(움직인 성분조차 변동계수 0.758) → 어떤 거리 모델도 이 바닥을 넘지 못함.
- **배차 이동비용 = 순수주행(구간시간) 그리드(잠정)** — 2단계 이동비용은 `learn_travel_zone225_drive`(225m OD 격자·**구간시간**(출발→도달; 경로 정체 포함·핸드오버 제외) p50/p90) 참조, L3 폴백 = quay_manhattan_m ÷ 3.30 m/s(13km/h·구간속도). 실현시간(핸드오버 포함, `learn_travel_zone225`)은 계속 갱신하나 비용에는 미사용(참조용). **[2026-07-01 정정]** 한때 "움직인 순간만(drive_s)"으로 뒀으나 경로 정체까지 벗겨 틀렸으므로 구간시간으로 교정.

## 다음 (우선순위순)

### 1) 사이클 v2 승격 검토
v2 그림자가 경계(열림/닫힘) 정확도에서 v1을 추월하고 trip 포착도 개선됨. 메인 지표를 v2로 교체할지 게이트로 판단 — [실험](/kc/experiments/cycle-v2-shadow/) 참고.

### 2) AI 배차 — 예측 모형
누적된 `tt_cycle_log`/`tt_cycle_v2`를 연료로 예측 라벨 정의·베이스라인 측정. [리서치](/kc/research/tt-prediction/).

**OD 이동시간 모델(설계 목표·미구축)**: OD 주행시간 = 학습 모델(그래디언트 부스팅 계열). 라벨 = **구간시간**(출발→도달). 피처 = 도로망 경로거리 + 맨해튼 + 날씨(비 ~5% 느림) + 혼잡(`congestion_edge`·전용도로라 주행속도 영향 ≈0) + 시간대. 지금의 225m 격자 조회를 이 모델이 대체한다.

### 2b) 1단계 마감여유 = 여정 기반
- **1단계 lead 재보정(완료)**: 배차 마감 = work_eta − lead에서 lead를 고정값(양하 300·적하 1200)에서 **실측 여정 p75**(양하 450·적하 1180)로. 양하 lead = 공차이동(픽업 크레인까지), 적하 lead = 공차이동+받기+부하이동(딜리버리 크레인까지). 상수 `LEAD_DS_S`/`LEAD_LD_S`.
- **[2026-07-01 정정] 크레인 진입 대기는 폐기**: 한때 크레인별 진입 대기(`learn_crane_approach`)를 1단계 신호로 넣으려 했으나, 일관된 방법으로 재보니 그 대기의 중앙값이 **거의 0**(옛 67초는 도착 전에 근처 찍힌 트럭만 센 편향)이고 크레인 도착 좌표도 부정확이라 **폐기**했다. 진짜 크레인 줄서기는 이동시간이 아니라 도착 이후(크레인 스케줄) 영역.

### 2c) 도로망 라우팅 — 검증 완료·미채택(부정 게이트)
- 225m 격자는 좁은 다리·일방통행을 표현 못 해(격자는 멀리 돌아가는 실제 경로를 인접으로 오판) 폐기 결정, 도로망 라우팅을 목표로 삼음.
- 추론 도로망은 매시 Python cron이 GPS→스켈레톤(skimage/sknw)→링크로 생성, `road_node`/`road_edge`(mig 0077·~264노드/353방향엣지)에 라우팅 가능하게 적재. Rust 방향 Dijkstra 라우터 `crates/api/src/roadgraph.rs`, 검증 로거 → `road_route_eval`(mig 0078).
- **게이트 결과(drive_s 라벨·585 스냅 레그)**: 도로 경로 상관 0.490 vs 맨해튼 0.565 → 도로가 더 나쁨. 게다가 스냅되는 레그는 30%뿐(작업지점이 도로망에서 중앙값 62m 벗어남·도로가 블록/안벽 안까지 안 들어옴). → **미채택**, 비용은 순수주행 격자 유지. 인프라는 향후 더 촘촘한 그래프의 **경로거리 피처** 공급용으로 보존.
