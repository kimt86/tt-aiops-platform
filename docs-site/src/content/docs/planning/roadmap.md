## 한 것 (요약)

- 실시간 대시보드 + KPI 7종 + websocket 정확도 보강.
- `idle→staging` 분류 교정, 라이브 배차 풀.
- **작업 사이클 적재** — `tt_cycle_log`(v1) + `tt_cycle_v2` 그림자.
- **사이클 v2** — 6-이벤트 모델(핸드오버 수집 포기), 픽업 레그 보장, CYCLES 페이지에 6이벤트 노출. 상세 [실험](/kc/experiments/cycle-v2-shadow/).
- **공차 레그 분해** — `learn_leg_decomp` **(retire됨 · mig 0081)**: 각 공차 레그의 움직임(drive_s)/정지(stop_s) 진단이었으나 제거. 비용 라벨(순수주행=구간시간)은 `learn_travel_sample` 빈트립으로 이관(mig 0080). 당시 규명한 발견: (a) ARRIVED ≈ 실제 도착(중앙값 −4초) → 큰 크레인 대기는 이동시간 **안이 아니라 ARRIVED 이후**, (b) 예전 "중앙값 6.9km/h"는 직선÷정지포함시간÷짧은레그 가중 착시, (c) 같은 OD여도 크게 흩어짐(변동계수 0.758) → 어떤 거리 모델도 이 바닥을 넘지 못함.
- **배차 이동비용 = 도로망 경로시간 → 실제시간 곡선 (2026-07-02)** — 2단계 이동비용은 추론 도로망(`road_node`/`road_edge`) 위 최단시간 경로를 **실측 곡선**으로 변환(`road_route_eval`에서 "이 경로시간이면 실제 보통 N초"를 구간별 실제 p50/p90 매듭으로 학습 — 단조 잠금·짧은 경로 바닥 ~89초 유지). 폴백(라우팅 불능 ~3%) = 같은 표의 맨해튼 거리→실제 곡선(거리÷3.30 m/s 어림은 콜드스타트만). 잰 값의 정의는 **순수주행=구간시간**(출발→도달; 경로 정체 포함·핸드오버 제외). 225m 격자 룩업(`learn_travel_zone225_drive`)은 **폐기**(mig 0082). 실현시간(핸드오버 포함, `learn_travel_zone225`)은 계속 갱신하나 비용에는 미사용(참조용). **[2026-07-01 정정]** 한때 "움직인 순간만(drive_s)"으로 뒀으나 경로 정체까지 벗겨 틀렸으므로 구간시간으로 교정. **[2026-07-02 정정]** 처음의 "비율(1.4/0.4배) 곱 보정"은 당일 리뷰에서 탈락(비단조 역전·바닥 소실) → 직접 곡선으로 교체.

## 다음 (우선순위순)

### 1) 사이클 v2 승격 검토
v2 그림자가 경계(열림/닫힘) 정확도에서 v1을 추월하고 trip 포착도 개선됨. 메인 지표를 v2로 교체할지 게이트로 판단 — [실험](/kc/experiments/cycle-v2-shadow/) 참고.

### 2) AI 배차 — 예측 모형
누적된 `tt_cycle_log`/`tt_cycle_v2`를 연료로 예측 라벨 정의·베이스라인 측정. [리서치](/kc/research/tt-prediction/).

**OD 이동시간 모델(현행 = 경로시간→실제 곡선)**: 라벨 = **구간시간**(출발→도달). 현행 모델 = **도로망 경로시간을 실측 "실제시간 곡선"으로 변환**(구간별 실제 p50/p90을 계속 학습) — 격자 조회는 대체 완료(2026-07-02). 다음 개선은 피처 추가보다 **도로망 자체**(찻길 속도 정밀화·혼잡 가중·일방 정확도)에 있다(날씨 비 ~5%·혼잡 ≈0으로 측정상 신호 미미). 어떤 모델도 시간↔거리 상관 ~0.38(대기 노이즈) 천장은 못 넘으므로 출력은 항상 p50/p90 분포.

### 2b) 1단계 마감여유 = 여정 기반
- **1단계 lead 재보정(완료)**: 배차 마감 = work_eta − lead에서 lead를 고정값(양하 300·적하 1200)에서 **실측 여정 p75**(양하 450·적하 1180)로. 양하 lead = 공차이동(픽업 크레인까지), 적하 lead = 공차이동+받기+부하이동(딜리버리 크레인까지). 상수 `LEAD_DS_S`/`LEAD_LD_S`.
- **[2026-07-01 정정] 크레인 진입 대기는 폐기**: 한때 크레인별 진입 대기(`learn_crane_approach`)를 1단계 신호로 넣으려 했으나, 일관된 방법으로 재보니 그 대기의 중앙값이 **거의 0**(옛 67초는 도착 전에 근처 찍힌 트럭만 센 편향)이고 크레인 도착 좌표도 부정확이라 **폐기**했다. 진짜 크레인 줄서기는 이동시간이 아니라 도착 이후(크레인 스케줄) 영역.

### 2c) 도로망 라우팅 — 재구축해서 배차 비용에 채택(2026-07-02)
- 225m 격자는 좁은 다리·일방통행을 표현 못 해(격자는 멀리 돌아가는 실제 경로를 인접으로 오판) 폐기 결정, 도로망 라우팅을 목표로 삼음.
- 추론 도로망은 매시 Python cron이 GPS→스켈레톤→링크로 생성해 `road_node`/`road_edge`에 적재. Rust 방향 Dijkstra 라우터 `crates/api/src/roadgraph.rs`, 검증 로거 → `road_route_eval`.
- **1차 게이트는 탈락이 맞았다**(옛 264노드 판): 상관이 맨해튼보다 낮고 작업지점 30%만 스냅(중앙 52m 벗어남). **재구축(2026-07-02)**: 조밀화(35m 분절) + **작업지점 5,888곳 커넥터**(스냅 100%) + **방향은 부모 도로 다수결**(조각별 결정은 방향 충돌로 경로 단절) + 지오메트리 기점 정렬 — 성공률 46.6→96.7% + 트럭 출발점 스냅 150m → **7,189노드로 재적재·배차 비용에 배선**(위 2 항목). 상시 게이트(`road_route_eval`)로 경로시간 vs 맨해튼을 계속 측정(현재 0.358 vs 0.385 대등 — 격자형 터미널이라 경로거리≈맨해튼 상관 0.998). 채택 근거 = 정확도가 아니라 **천장**(찻길 속도·혼잡 반영 여지)과 **비격자 터미널 일반화**.
