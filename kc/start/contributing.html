글쓰기 규칙

이 규칙은 모든 글에 일관되게 적용됩니다. 새 글을 쓰기 전에 먼저 읽으세요.

규약 리빙 문서

파일 · 제목

  • 파일명은 영문 kebab-case (cycle-detection.html). 화면 제목은 한국어.
  • 파일은 알맞은 섹션 폴더에 두고(kc/<섹션>/<슬러그>.html), 나브에 등록합니다 — kc/assets/kc.js의 NAV에 { page: "섹션/슬러그", title: "제목" } 한 줄 추가.

페이지 골격

모든 페이지는 본문만 담고, 공용 셸(사이드바 · TOC · 검색 · 이전/다음)은 kc.js가 자동 주입합니다. 최소 골격:

<main class="kc-article" data-page="섹션/슬러그" data-source="원본.md">
  <h1>한국어 제목</h1>
  <p class="kc-lede">한 줄 요약</p>
  <div class="kc-meta">
    <span class="kc-badge kind">리서치</span>
    <span class="kc-badge living">리빙 문서</span>
  </div>
  ... <h2>/<h3> 본문 (우측 TOC 자동 생성) ...
</main>
  • data-page = 나브 매칭·브레드크럼·이전/다음의 키. data-source = 원본 경로(툴바에 표시, 선택).
  • 콜아웃은 <div class="kc-cal note|tip|warn|danger"><span class="h">제목</span> …</div>.
  • 표는 <div class="kc-tablewrap"><table>…</table></div>로 감싸 가로 스크롤을 보장합니다.

상태표시 (리서치 · ADR · 실험)

사실 정확성이 중요한 글은 상단 kc-meta에 상태 배지를 답니다:

  • 종류 — 리서치 / ADR / 실험 / 레퍼런스 등
  • 리빙 문서 — 현행 유지 · 계속 갱신
  • 검토 필요 — 오래됐거나 상위 변경 미반영

★ 사실 원칙 — 추측을 사실처럼 쓰지 않기

이 프로젝트의 가장 비싼 자산은 검증된 지식입니다. 그래서:

  • 검증 안 된 구체 수치 · 식별자 · API 동작은 단정하지 않는다. (미검증)으로 표기하고 글 끝의 "열린 질문" 절에 남긴다.
  • 관측 못 한 값은 비워 둔다(NULL). 그럴듯한 추정으로 채우지 않는다.
  • 외부 사실(API 명세 · 수치)은 1차(공식) 출처를 확인하고 출처를 남긴다. 모르면 "모른다"고 적는다.
  • 정정 · 번복도 지우지 말고 기록한다.
왜 이렇게까지

"그럴듯하지만 틀린" 사실 하나가 나중에 몇 시간을 잡아먹습니다. 불확실하면 (미검증)이 정직하고 더 빠릅니다.

링크

  • 내부 문서는 /kc/<섹션>/<슬러그>.html 절대경로로 상호 링크합니다. 예: <a href="/kc/start/overview.html">개요</a>.
  • 사이트가 /kc/로 서빙되므로 /kc 접두사가 필요합니다. 빼면 대시보드 SPA로 가버려 깨집니다.

문체

  • 결론을 먼저, 근거는 나중. 군더더기 없이.
  • 한국어로 쓰되, 기술 용어는 처음 등장 시 한글(영문)처럼 병기. 예: 트랜스퍼 트럭(TT), 의사결정 기록(ADR).
  • 표 · 코드블록 · 콜아웃(kc-cal)을 적극 활용.
  • 새 글은 이미 있는 페이지의 골격을 복사해서 시작하세요.
