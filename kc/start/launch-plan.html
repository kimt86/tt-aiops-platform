한 줄 요지

모델과 배차 로직은 이미 라이브 그림자로 성숙하게 돌고 있습니다. 더 만들 모델이 남은 게 아니라, 정식 전환의 관건은 네 가지입니다 — ① 권고를 내보내는 출력 채널, ② 우리가 더 낫다는 정량 증거, ③ 24/7 운영 견고성, ④ 단계적 파일럿.

2026-08-11 기준으로 ④의 앞자리인 운영자 화면(배차 보드)은 완성됐습니다. 남은 병목은 우리 손 밖에 있는 것(TOS가 권고를 받는 방법, 폴백 보증, 판정 기준 합의)과 우리 손 안에 있는 것(작업목록이 낡았을 때 멈추는 안전장치, 무인 운영용 실패 알림)으로 뚜렷이 갈립니다.

이전 판에 있던 두 숫자를 뺐습니다

"2단계 실현가능성 81.8%" — 마감 안에 도착하는 추천의 비율입니다. 2026-08-06에 작업 고르는 방식을 바꾸면서 이 숫자를 품질 점수로 쓸 수 없게 됐습니다. 새 방식은 이미 늦은 작업을 일부러 목록에 담기 때문에, 비율이 낮아진 것이 나빠진 것인지 담는 대상이 달라진 것인지 이 숫자만으로는 구분되지 않습니다.

"최적 매칭 이득 −5.1%" — 문서마다 40% · 38~43% · −5.1% 로 다르게 적혀 있고, 무엇을 무엇과 비교한 값인지도 서로 다릅니다. 대외로 인용할 수치 하나를 확정하기 전까지 여기서는 싣지 않습니다(아래 B3).

남은 작업 — 4개 워크스트림

유형: [기술] · [조직] · [기술+조직]

A. 출력 · 통합 🔴 크리티컬 패스

지금 우리 권고는 내부 기록과 사내 화면에만 있습니다. "서비스"가 되려면 외부가 구독 · 소비할 채널과 계약이 필요합니다.

  • 🔨 A1 · 브로드캐스트 채널 구현 [기술] — 배차 권고를 외부 구독용 안정 API/피드로. 스키마 · 주기 · 재전송 · 인증.
    진척: 추천에 컨테이너번호가 실렸습니다(2026-08-10). 이전에는 "어느 크레인의 어느 묶음"까지만 있어 상자 한 개를 지목할 수 없었는데, 그 결정적 제약이 풀렸습니다. 사내용 조회 주소도 생겼습니다. 남은 것은 외부용 계약 — 인증 · 재전송 · 중복 방지 규약.
  • ⬜ A2 · TOS/운영측 계약 합의 [기술+조직] — 무슨 필드를 · 얼마나 자주 · 어떤 의미로 넘기고 TOS가 어떻게 소비할지. (A1 선행 · 조직 합의)
  • ⬜ A3 · 신선도 · 지연 검토 [기술] — 60초 주기가 충분한지, 이벤트 기반 즉시 갱신 필요 여부.

B. 신뢰 확보 (검증)

  • ✅ B1 · 유휴 리드타임 한계 확정 [기술] — "몇 분 후 빌지"는 관측 신호로 개별 예측 불가로 결론(세 각도) → 중앙값 + 보수적 p90 방어. ADR 0002. 재추진 금지.
  • 🔨 B2 · 이동시간 GBM 그림자 → 배선 [기술] — 며칠 이기면 배차 경로에 서빙.
  • 🔨 B3 · "TOS보다 낫다"의 정량 증거 [기술+조직] — 수주간 · 시나리오별 공정비교.
    진척: 비교 방식을 상자 한 개 단위로 다시 짰습니다(2026-08-10, 비교 해설). 같은 상자를 두 시스템이 각각 어느 트럭에 · 언제 줬는지를 나란히 놓는 방식이라, 이전의 "평균 대 평균" 비교보다 반박하기 어렵습니다.
    남은 것: 대외 인용 수치 하나와 그 정의문 확정. 지금은 문서마다 값이 달라 Go/No-Go 판정을 내릴 수 없습니다.
  • ✅ B4 · 실현불가 규명 [기술] — 규명됨. 마감이 틀린 것도 트럭이 먼 것도 아니었고, 비교 대상이 어긋나 있었습니다: 적하는 트럭이 야드 블록에 닿는 시각을 안벽 크레인이 필요한 시각과 맞대고 있었습니다. 그 사이의 싣고 가는 구간이 통째로 빠져 있었고(실측 약 18분), 채워 넣자 현장 실제와 맞았습니다.

C. 운영 견고성

  • ⬜ C1 · 장애 대응 · 강등 · 폴백 [기술] — 웹소켓 끊김 · 추출기 정지 · 모델 이상값 시 우아한 강등과 안전한 폴백.
    알려진 구멍(우리가 고칠 수 있는 것): 위치 신호가 끊기면 계산을 건너뛰지만, 작업목록이 낡은 것은 검사하지 않습니다. 목록을 받아오는 쪽이 멈춰도 옛 목록으로 추천을 계속 냅니다. 지금은 그림자라 기록만 지저분해지지만, 실제 배차로 올리면 곧바로 잘못된 지시가 됩니다. 우선 처리 대상.
  • 🔨 C2 · 배차 파이프라인 모니터링 · 알림 [기술] — 배차 자체의 헬스 · 지연 · 이상 감시.
    진척: 트럭도 작업도 있는데 추천이 0건인 상태가 3분 이어지면 경보가 뜹니다. 계산이 30분간 멈추면 잡는 감시도 있습니다. 화면에는 마지막 계산이 얼마나 오래됐는지가 상시 표시됩니다.
    남은 것: 자료를 받아오는 일회성 작업들이 실패했을 때는 아직 알림이 없어, 사람이 화면을 봐야 압니다.
  • ⬜ C3 · 프로덕션 하드닝 [기술] — 연구/그림자 코드베이스를 무인 운영 등급으로. 배차를 고르는 로직에 자동 검사가 아직 없습니다 — 고칠 때 실수를 잡아줄 안전망이 없다는 뜻입니다.

D. 파일럿 · 조직 🔴 결정 필요

  • ⬜ D1 · 단계적 롤아웃 + 롤백 설계 [기술+조직] — 자문 → 부분 → 전면, 각 단계 진입/통과 기준과 롤백 절차.
  • ✅ D2 · 운영자 UI [기술] — 배차 보드 완성(2026-08-10). 급한 순 추천 목록 · 마감까지 남은 시간 카운트다운 · 오래된 화면은 회색 처리 · 계획에서 추천까지 몇 개가 어디서 걸러졌는지 보여주는 깔때기 · 지도 위 추천선. 관제와는 주소 뒤에 #board를 붙여 공유합니다. 보드 해설
  • ⬜ D3 · 수용기준 · 책임 · 교육 [조직] — 우리 배차가 틀렸을 때의 권한/책임, 운영자 교육, TOS팀 통합.
    참고: 운영자가 권고를 받아들였는지 무시했는지를 직접 기록하는 장치는 아직 없습니다. 지금 있는 것은 "TOS가 결과적으로 같은 상자를 골랐는가"뿐이라, 사람의 판단을 재는 값이 아닙니다.
크리티컬 패스

A1→A2(출력 채널 + 계약)와 D1(파일럿 설계)가 병목이며 둘 다 조직 합의가 필요합니다. B1(유휴 리드타임)은 관측 한계로 확정(ADR 0002) — 리드타임에 매달리지 말고 이 세 갈래에 집중.

우리 손 안에서 먼저 끝낼 것(합의를 기다릴 필요 없음): C1의 작업목록 신선도 검사 → C2의 실패 알림 → C3의 자동 검사. 이 셋이 닫히면 자문 단계를 막는 기술적 이유는 남지 않습니다.

단계적 롤아웃 — 날짜가 아니라 게이트로

Phase 0 · 그림자 (현재)

계산 · 권고 · 검증만. 실제 차량 지시는 TOS. 모든 모델 · 로직이 라이브로 돌며 실측과 대조됩니다.

통과 기준 — B3 "TOS보다 낫다" 초기 증거 확보. (B1 유휴 리드타임은 관측 한계로 확정 — ADR 0002)

Phase 1 · 자문 (Advisory)

운영자가 우리 권고를 화면으로 봅니다 — 제어는 하지 않음. 실제 채택은 사람이 판단.

필요 — A1 출력 · D2 운영자 UI ✅ · C2 모니터링(부분 완료)
통과 기준 — 운영자 수용 + 권고 신뢰 + 무중단 안정.

화면은 준비됐습니다. 이 단계로 넘어가려면 남은 것은 작업목록 신선도 검사(낡은 목록으로 추천하지 않기)와 운영자가 받아들였는지를 기록하는 장치입니다 — 뒤엣것이 없으면 다음 단계로 갈 근거를 만들 수 없습니다.

Phase 2 · 부분 (Partial)

일부 트럭/레인/교대에만 우리 배차를 실제 적용. 나머지는 TOS. 범위를 좁혀 위험을 가둡니다.

필요 — A2 계약 · C1 폴백 · D1 롤백 · D3 책임
통과 기준 — 부분 범위에서 TOS 대비 개선 입증 · 무사고 · 폴백/롤백 실증.

Phase 3 · 전면 (Full)

전 트럭을 우리 배차로. TOS는 감독 · 예외 처리. 정식 서비스.

전제 — Phase 2 지표 지속 + C3 프로덕션 하드닝 완료 + 조직 최종 승인.

위험 · 미결정

  • 조직 합의가 최대 불확실성 — TOS팀 통합 · 책임 소재 · 수용 기준 미정. 기술이 준비돼도 이게 없으면 Phase 1조차 못 넘음. → 조기 착수 권장.
  • "낫다"의 정의 미합의 — 공정비교 기준이 합의 안 되면 게이트 판정 불가. B3와 함께 지표 정의를 먼저 확정.
  • 곧-가용 후보는 태생적으로 흐릿함(확정) — 유휴 리드타임은 개별 예측 불가(ADR 0002). 보수적 p90으로 방어하되 지금 유휴 + 방금 빈 트럭에 주로 기대는 설계가 맞음.
