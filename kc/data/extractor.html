추출기(Extractor) 아키텍처

tt-extractor(바이너리 extractor)는 TOS 프로덕션 Oracle을 건드리는 유일한 컴포넌트이자, TOS→Postgres 적재의 심장입니다. 이 문서는 그 구조·역할·서비스에서의 위치를 한곳에 정리한 아키텍처 레퍼런스입니다. "무엇을 긁는가"(추출 지점 전수)는 → TOS 데이터 추출 전수, 여기는 "어떻게 도는가"(엔진).

데이터 · 아키텍처전수 매핑 2026-07-22 · 정리 mig0101
Bottom line

추출기는 두 갈래입니다: ① 증분 스트림(qc-moves·rtg-moves·handover·workpool — 60초, 근실시간 이벤트 로그) ② KPI 롤업(tick·nightly — 하루/시프트 집계). 모든 Oracle 접근은 단일 게이트(remote-toolbox-sql)로 읽기전용·인덱스안전·캡·직렬. 흐름은 Oracle → 추출기 → Postgres(L0/L1/L2·이벤트로그·live) → API/대시보드. 무게(부하)에 따라 주기를 다르게 둡니다(값싼 MCH 스트림은 자주, 무거운 JOB_HISTORY 집계는 드물게·야간).

2. Oracle 접속 메커니즘 & 안전 (가장 중요)

TOS는 실운영 프로덕션 DB라 부하가 곧 현장 리스크입니다. 그래서 안전이 구조적으로 강제됩니다:

원칙구현
단일 게이트runner.rs의 Toolbox만 Oracle에 닿음 — remote-toolbox-sql 스킬 스크립트를 통해. 다른 어떤 모듈도 직접 Oracle 접근 안 함.
직렬화프로세스 전역 static ORACLE_LOCK: Mutex — run_sql이 먼저 락을 잡아 두 쿼리가 동시에 Oracle에 못 감.
읽기전용스킬이 SELECT만 허용(읽기전용 툴박스). 손상 불가.
인덱스 안전모든 술어가 인덱스 타는 형태(날짜 등가/범위·PK seek). params.rs가 문자열 리터럴로만 렌더(바인드·Oracle 날짜연산 없음).
캡모든 쿼리에 FETCH FIRST n ROWS ONLY. 90초 타임아웃. SQL은 argv 아닌 임시 파일로 전달(셸 이스케이프 손상 방지).
⚠ 알려진 함정

① 툴박스는 SQL에 단독 >가 있으면 HTTP 400(부등호는 >=/BETWEEN 사용). ② ORACLE_LOCK은 프로세스 내만 직렬화 — qc/rtg/handover는 독립 서비스라 매분 겹칠 수 있음(정상 seek 속도라 무해하나, 회귀 시 배가). ③ 딕셔너리(all_ind_columns 등)로 인덱스 먼저 확인 후 본 테이블 조회.

4. 증분 스트림 — 근실시간 이벤트 피드

워터마크로 새 꼬리만 seek해 이벤트 로그에 적재. 셋 다 Phase-2 지상 진실(ground truth) — 웹소켓 추정 싸이클을 교정/백필합니다.

스트림소스 → 타깃워터마크 seek다운스트림
qc-movesMCH_OPERATION[C/M/Z] → qc_move_logSEQNO PK-seek(SEQNO=완료 순서·PK 선두)DS 픽업·LD 드롭 핸드오버 진실
rtg-movesMCH_OPERATION[RTG/ES] → rtg_move_logSEQNO PK-seek(동일)RTG 전 작업믹스 = 대기예측 피처
handoverJOB_ORDER_HISTORY[C] → tos_handover_labelconcat FBI seek(DATE‖TIME 함수기반인덱스)soon-idle 정답 + tt_move_log 앵커
★워터마크 = "재스캔"이 아니라 "seek" (핵심 설계)

증분 폴은 정렬된 인덱스 선두 컬럼에 워터마크를 걸어 "지난 지점부터"만 읽어야 합니다. MCH_OPERATION은 SEQNO(PK 선두·전역 시간 시퀀스)로, JOB_ORDER_HISTORY는 DATE‖TIME concat에 독립 함수기반인덱스가 있어 그 concat으로 seek. 둘 다 폴 비용이 주기와 무관(~0.8s seek)해 60초 주기가 안전합니다. 계산식(concat) 술어를 인덱스 없이 쓰면 매 폴이 오늘치를 재스캔하므로 금물 — 이게 이 설계의 요점.

무손실 가드(qc/rtg): ① 워터마크에서 120초 안전랙을 빼고 seek → 늦게/역순으로 보이는 행도 재읽고 ON CONFLICT dedup. ② >=(동초 비유일 skip 방지). ③ 워터마크 전진은 14자리 숫자 SEQNO에만(오정렬 stall 방지). handover는 >=+ON CONFLICT로 경계 갭 방지.

L0 → L1 → L2 파이프라인

KPI 추출은 raw_k_*(L0·멱등 upsert)에 적재만. 순수 Postgres transform이 raw_k_*를 kpi_daily(L1·헤드라인 K_UTIL/K_EMPTY/K_CYCLE/K_RTG_Q/K_MPH…)로 굴리고, baseline이 4주 기준·Welch 유의검정으로 kpi_baseline(L2). tick=오늘잠정(is_provisional)·nightly=최종(잠정이 최종을 덮지 않음).

9. 설계 원칙 (요약)

  • Oracle은 추출기만 — 단일 게이트·직렬·읽기전용·인덱스안전·캡. 부하가 곧 현장 리스크.
  • 증분은 seek, 집계는 바운드 — 증분 폴은 인덱스 선두 컬럼 워터마크로 seek(주기 무관); 집계는 인덱스 날짜 등가로 바운드.
  • 무게별 주기 — 값싼 MCH 스트림 자주(60초), 무거운 JOB_HIST 집계 드물게/야간.
  • PARTIAL — 개별 KPI 실패는 건너뛰고 계속(전 스트림 run_logged가 etl_run_log+data_freshness에 기록).
  • L0→L1→L2 — 추출(raw)·변환(kpi_daily)·기준(baseline) 분리; 변환/기준은 Postgres 전용.
  • MYT(UTC+8) 전역 — parse_etw로 YYYYMMDDHH24MISS[mmm] → UTC.
