3. 동시에 몇 개가 도나

  • 각 수집은 서로 다른 프로그램(타이머)으로 돕니다. 한 프로그램 안에서는 Oracle 조회가 한 번에 하나씩만 나갑니다.
  • ①과 ②는 같은 초(05·20·35·50초)에 함께 시작합니다. 실행 기록에서도 두 시작 시각이 같은 초로 찍혀 있습니다. 그래서 15초마다 최소 두 개가 동시에 나갑니다.
  • 5분마다 35초에는 ⑦도 같은 초에 시작해 세 개가 겹칩니다.
  • 나머지 ③④⑤⑥은 25·40·55·15초로 시작 초를 나눠 두었습니다.

4. 헷갈리기 쉬운 것 — 지금은 Oracle 을 안 쓰는 것

이름만 보면 Oracle 을 읽을 것 같지만 지금 설정에서는 읽지 않습니다
  • 교대 실시간 지표(3분·15분마다 — 시간당 무브 수, 크레인 대기, 사이클, 빈 차 주행 등): 모두 우리 DB 의 사본(①②④가 채운 표)으로 계산합니다. 15분 주기 묶음 중 Oracle 에 닿는 것은 ⑧ 하나뿐입니다.
  • 야간 지표 9개: 8개는 우리 사본으로 계산하고, Oracle 을 읽는 것은 ⑩ 하나와 점검 ⑪뿐입니다.
  • ETW(크레인 작업 예정 시각): 1분마다 받지만 Oracle 이 아니라 별도 게이트웨이(HTTP)에서 받습니다.
  • 트럭 GPS · 날씨: Oracle 과 무관합니다.
  • API 서버(화면·배차 계산): 설계상 Oracle 에 붙는 수단이 아예 없습니다. 모든 Oracle 조회는 추출기 한 곳에서만 나갑니다.
  • ⑤를 검증하는 2초 간격 실측 도구(scripts/tos_avail_truth/run.sh): 사람이 손으로 돌릴 때만 돌며, 상시로는 돌지 않습니다.

위의 교대·야간 지표는 스위치를 바꾸면 예전처럼 Oracle 을 읽게 할 수 있습니다(§7). 그렇게 바꾸면 이 표의 숫자도 달라집니다.

5. 이 숫자를 어떻게 쟀나

  • 주기: 이 서버에 설치된 타이머 설정(복사본, 저장소의 deploy/systemd 와 내용이 같음을 확인)을 읽었습니다. 타이머는 서버 시계(한국 시각)로 적혀 있어 MYT 로 바꿔 적었습니다. 예: 야간 01:30 KST = 00:30 MYT. 실행 기록의 야간 시작도 00:31 MYT 였습니다.
  • 하루 횟수·소요·행: 우리 DB 의 실행 기록 표(etl_run_log)에서 2026-10-13 14:33 ~ 10-14 14:31 MYT 24시간 동안의 실행을 셌습니다. 분모는 "그 24시간 동안 시작한 실행 한 번"입니다. 실패는 24시간 동안 0건이었습니다.
  • 1회 소요는 Oracle 만의 시간이 아닙니다. 우리 쪽에서 잰 한 번 실행의 전체 시간(중계 서버 접속 + Oracle 조회 + 우리 DB 에 담기)입니다. 그래서 Oracle 이 실제로 일한 시간은 이보다 짧습니다. Oracle 쪽 시간은 따로 재지 않았습니다.
  • 위 소요를 하루치 모두 더하면 15,118초(하루의 17.5%)입니다. 이것은 "우리 조회가 하나라도 진행 중이던 시간"의 상한이지, Oracle 사용량이 아닙니다.
  • ⑫의 시나리오 수집기는 별도 저장소(~/projects/tt-scengen)의 코드를 읽어 확인했습니다. 5분마다 깨어나지만 요청된 날이 없으면 우리 DB 만 보고 끝납니다.

6. SQL 원문

실제로 나가는 질의를 그대로 옮겼습니다(설명 주석만 뺐습니다). {…}, {{…}}, __VOYAGES__ 처럼 생긴 자리는 실행할 때 코드가 채우는 값입니다. 예를 들어 "지난번 지점", "지금 시각", "작업 중인 항차 목록"이 들어갑니다.

① 안벽 크레인 작업 기록 — 15초

SELECT
       MCH_OPER_MACHNO AS machno, SUBSTR(MCH_OPER_CONTNO,1,11) AS contno,
       MCH_OPER_SEQNO AS seqno, MCH_OPER_JOBTYPE AS jobtype, TRK_ID AS trk_id,
       ST_DT AS st_dt, MCH_OPER_COMPDATE||MCH_OPER_COMPTIME AS comp_dt,
       MCH_OPER_STATUS AS status, MCH_OPER_QUEUENAME AS queuename,
       MCH_OPER_VESSEL AS vessel, MCH_OPER_VOYAGE AS voyage,
       MCH_OPER_ISO AS iso
  FROM TOSADM.MCH_OPERATION
 WHERE MCH_OPER_SEQNO >= '{seek_from}'
   AND MCH_OPER_SEQNO <= '{until}'
   AND MCH_OPER_MACHNO IN (SELECT CDY_MCHN_CODE FROM TOSADM.CDY_MACHINE
                            WHERE CDY_MCHN_TYPE = 'QC')
   AND LENGTH(MCH_OPER_COMPTIME) >= 6
 ORDER BY MCH_OPER_SEQNO
 FETCH FIRST 5000 ROWS ONLY

⑩ 하루 사이클 지표 — 하루 1번

{{DAY_STR}} 자리에 어제 날짜가 들어갑니다. 야간 실행에서는 {{TIME_PREDICATE}} 가 비어 하루 전체를 봅니다.

WITH job_events AS (
  SELECT JOB_HIST_JOBTYPE,
         JOB_HIST_CONTNO, JOB_HIST_POINT, JOB_HIST_SEQNO,
         COUNT(*) AS transitions,
         MIN(JOB_HIST_DATE||JOB_HIST_TIME)   AS first_evt,
         MAX(JOB_HIST_DATE||JOB_HIST_TIME)   AS last_evt
    FROM TOSADM.JOB_ORDER_HISTORY
   WHERE JOB_HIST_DATE = '{{DAY_STR}}'
   {{TIME_PREDICATE}}
   GROUP BY JOB_HIST_JOBTYPE, JOB_HIST_CONTNO, JOB_HIST_POINT, JOB_HIST_SEQNO
),
cycles AS (
  SELECT JOB_HIST_JOBTYPE,
         transitions,
         (TO_DATE(SUBSTR(last_evt,1,14),'YYYYMMDDHH24MISS')
        - TO_DATE(SUBSTR(first_evt,1,14),'YYYYMMDDHH24MISS')) * 86400 AS cycle_sec
    FROM job_events
   WHERE transitions > 1
),
stats AS (
  SELECT JOB_HIST_JOBTYPE,
         COUNT(*)                AS jobs,
         AVG(cycle_sec)          AS avg_cyc,
         STDDEV(cycle_sec)       AS std_cyc,
         MEDIAN(cycle_sec)       AS med_cyc,
         AVG(cycle_sec) + 2 * STDDEV(cycle_sec) AS thr,
         PERCENTILE_CONT(0.25) WITHIN GROUP (ORDER BY cycle_sec) AS p25,
         PERCENTILE_CONT(0.75) WITHIN GROUP (ORDER BY cycle_sec) AS p75,
         PERCENTILE_CONT(0.95) WITHIN GROUP (ORDER BY cycle_sec) AS p95,
         AVG(transitions)        AS avg_trans
    FROM cycles
   GROUP BY JOB_HIST_JOBTYPE
)
SELECT
       s.JOB_HIST_JOBTYPE                    AS jobtype,
       s.jobs,
       ROUND(s.avg_cyc, 1)                   AS avg_sec,
       ROUND(s.med_cyc, 1)                   AS med_sec,
       ROUND(s.std_cyc, 1)                   AS std_sec,
       ROUND(s.p25, 1)                       AS p25_sec,
       ROUND(s.p75, 1)                       AS p75_sec,
       ROUND(s.p95, 1)                       AS p95_sec,
       ROUND(s.thr, 1)                       AS outlier_threshold_sec,
       (SELECT COUNT(*) FROM cycles c
         WHERE c.JOB_HIST_JOBTYPE = s.JOB_HIST_JOBTYPE
           AND c.cycle_sec > s.thr)          AS outlier_n,
       ROUND(s.avg_trans, 2)                 AS avg_transitions
  FROM stats s
 ORDER BY s.jobs DESC
 FETCH FIRST 15 ROWS ONLY

TOS 데이터 추출 전수는 TOS 팀과 공유·승인을 받으려고 만든 자세한 설명서입니다(부하 산정, 컬럼별 의미 포함). 이 문서는 지금 실제로 도는 것만 짧게 맞춰 본 목록입니다. 두 문서가 다르면 이 문서의 측정 시점을 확인하세요. 2026-10-14 에 맞대 보니 다음이 달랐습니다.

  • 기존 문서는 시나리오 수집의 상자 크기 조회(CYY_CONTAINER)와 게이트 조회(CYC_HISTORY)를 5분마다 상시로 적고 있습니다. 지금은 상시로 돌지 않고, 게이트 조회만 하루치 요청 때 돕니다(⑫). 상자 크기 조회는 타이머가 없습니다.

  • 기존 문서의 1회 소요(①② 약 2초)보다 지금 측정이 짧습니다(0.3~0.4초). 이 문서의 소요는 우리 쪽에서 잰 전체 시간입니다.
