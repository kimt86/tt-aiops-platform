TOS DB 종합 레퍼런스

Westports TOS(Oracle) — 제품이 쓰는 권위적 데이터 원천의 테이블·컬럼·보존특성·코드. "어디서 무엇이 나오고, 얼마나 남고, 무엇을 조심해야 하는가"의 단일 진실 소스.

레퍼런스리빙 문서

개요 · 데이터 아키텍처

데이터는 두 원천에서 나와 Postgres 3-tier로 흐릅니다. 대시보드/API는 Postgres만 읽고, prod Oracle은 추출기만 건드립니다(읽기전용·인덱스레인지·FETCH FIRST·NO_PARALLEL).

TOS Oracle  ──(추출기: 일/교대 틱)──▶  Postgres L0 raw_* ──▶ L1 kpi_daily ──▶ L2 baseline
TOS Oracle  ──(추출기: 작업풀 90s)────▶  Postgres live_workqueue/live_workpool
websocket   ──(SSH 터널 → API 인제스트)▶ 메모리(라이브맵·배차)  ※DB 미적재
대시보드/API ──읽기──▶ Postgres only    ※Oracle 직접 접근 절대 금지

보존 기간 — 가장 중요한 특성

TOS Oracle은 롤링 보존이라 오래된 날짜가 자동 삭제됩니다.

소스 테이블보존영향받는 KPI
JOB_ORDER_HISTORY약 15일공차·공차비율·사이클·핸드오버대기
MCH_OPERATION / VSS_STATISTICS≥ 35일MPH·QC대기·가동률·항차 통계
YT_DIS_DT/ACTV_DT오래된 날 희소K_RTG_Q
실무 결론 — 깊은 백필 불가

공차/사이클 ~15일, MPH/QC대기/가동률 ~35일까지만 백필 가능. 그 이전(특히 1~4월)은 Oracle에서 이미 삭제. 과거 깊이는 "추출을 시작한 시점"부터 앞으로만 영구 누적.

TOS Oracle 테이블

3.1 JOB_ORDER_HISTORY — 컨테이너 작업 이력

이동거리·사이클·크레인 큐 대기의 원천. 한 작업 = (CONTNO, POINT, SEQNO).

컬럼의미
JOB_HIST_DATE/TIME이벤트 날짜(인덱스 술어)/시각.
JOB_HIST_JOBTYPELD 적하·DS 양하·MO/MI 이적·RH 재취급·GI/GO 게이트.
JOB_HIST_CONTNO / POINT / SEQNO(CONTNO·POINT·SEQNO) = 한 작업.
JOB_HIST_ARMGC작업 크레인 ID. 주의: RTG·ES·XXX만 — C##(안벽)은 없음(야드측).
YT_DIS_DT → JOB_HIST_ACTV_DT차이 = 크레인 큐 대기(K_RTG_Q) = (ACTV_DT − YT_DIS_DT)·86400초.
LNDN_TRV_RNG / UN_LNDN_TRV_RNG적재거리 / 공차거리(미터). 공차비율 = Σ공차/Σ(적재+공차).
⚠ YT_DIS_DT 의미 재검토 (2026-07-15 소스 조사)

이 표는 YT_DIS_DT를 "TT 하차 시각"으로 서술하지만, TOS 소스(oss-core jobschedule.relay)와 데이터 대조 결과 실은 "DISpatch(배차 배정) 시각"입니다("DIS"=DIScharge 아님). 그러면 K_RTG_Q = ACTV_DT − YT_DIS_DT가 하차→활성이 아니라 배차→활성(≈전체 사이클)을 재는 셈이라 과대일 수 있어 감사 필요. 상세 조사 기록.

3.2 MCH_OPERATION — 크레인 작업 기록 (move 단위)

QC 생산성(MPH)·QC 유휴·크레인 가동률의 원천. 깊게 보존(≥35일).

컬럼의미
MCH_OPER_MACHNO^[CMZ][0-9]+$ = QC(안벽 STS — 장비 마스터 CDY_MACHINE_TYPE 확인 2026-08-10: C·M·Z 셋 다 QC이고 M·Z는 저번호 선석 담당), RTG% = 야드 크레인.
ST_DTmove 시작(단, 완료 시 소급 기록되는 큐잉 시각).
COMPDATE + COMPTIME완료(물리적 완료). 인덱스 술어 = COMPDATE.
TRK_ID이 move를 처리한 트럭(TT) ID.

인터벌 병합으로 크레인 가동 구간을 만들고, 병합 구간 사이의 갭 = QC 유휴(K_QC_NOMOVE).

3.3 VSS_STATISTICS — 항차 계획·실적

(선박, 항차)당 1행. 계획 물량·규격 혼합·공식 생산성(GQCR/NQCR = 공식 MPH). 30일 윈도우.

3.4 작업시간·장비 마스터 (가동률 입력)

테이블의미
MCH_WORKTIMETT 작업/로그인 세션 → 가동률(K_UTIL_TT).
MCH_WORKSTOPTT 정지/휴식 → 가동시간에서 차감.
CDY_MACHINE장비 마스터. TYPE='YT'로 TT 필터.

3.5 라이브 작업지시 — 작업 풀 (현재 진행/대기)

완료 이력(3.1~3.4)과 달리 지금 처리할 작업은 두 라이브 테이블에. 60초 추출 → TT 페이지. (차량·작업 풀 갱신)

JOB_ORDER_LIST 컬럼의미
JOB_ODR_JOBSTATUSA 활성 · Q 대기 · P 계획 · B 차단 · C 완료. 라이브 = A/Q/P/B + COMPDATE IS NULL.
JOB_ODR_YTNO배정된 TT. GPS device와 일치.
JOB_ODR_ETW_DTETW = 크레인 준비 시각. ETW − 현재 = 시급도.
JOB_ODR_ARMGC / CONTNO / YT_TOPOS야드크레인 / 컨테이너 / 야드 블록-베이.
JOB_QUEUE_SCHEDULE 컬럼의미
JOB_QUE_CRANENOQC(C##). websocket GPS/PLC 크레인 id와 직접 매칭.
JOB_QUE_SEQQC가 큐를 처리하는 순서.
TOTALQTY / COMPQTY잔여(백로그) = TOTAL − COMP.

코드 · 의미 사전

작업종류: LD 적하 · DS 양하 · MO/MI 구내이적 · RH 재취급 · GI/GO 게이트. 배차 핵심은 LD·DS·MO·MI.
장비 프리픽스: TT 야드트럭 · RTG 야드 갠트리 · C## 안벽(QC) · M## 모바일하버 · Z# 스트래들 · ES/RS 스태커.

PLC를 주는 크레인

실시간 PLC(ctab)는 동적 크레인 C/M/Z만 송신. RTG는 PLC 미수신 → 양하 블록측 핸드오버는 GPS·근접도로만 추정.

POINT_TYPE: 1 안벽 · 2 블록 side · 3 블록 end · 4 buffer · 5 게이트IN · 6 게이트OUT · 7 battery · 10 handler · 11 pinning. 레이아웃은 mm CAD → 아핀 투영으로 lat/lon(RMS ~70m).

7개 KPI 정의

KPI단위·방향정의 (소스)
K_EMPTY 공차거리km/Job · 낮↑Σ공차m / Σjobs / 1000
K_EMPTY_R 공차비율% · 낮↑Σ공차m / Σ(공차+적재)m
K_CYCLE 사이클타임s · 낮↑작업 첫~마지막 이벤트 간격의 jobs-가중평균
K_UTIL TT 가동률% · 높↑TT별 min(1, 가동분/경과분)의 평균·100 (avg-of-ratios)
K_QC_NOMOVE QC 대기s · 낮↑QC 병합 구간 사이 유휴 갭 평균
K_MPH QC 처리량move/hr · 높↑QC move/active-hour의 active_hours-가중평균
K_RTG_Q (숨김)s · 낮↑(ACTV_DT − YT_DIS_DT) — 야드 핸드오버 대기(위 caveat 참조)

서빙 모델 (PostgreSQL 3-tier)

계층역할
L0 raw (raw_*)Oracle 일 스냅샷(분자/분모 보존). 멱등 upsert.
L1 rollup (kpi_daily)KPI별 일 권위 값(트렌드·이력 소스).
L2 stats (kpi_baseline)4주 롤링 + Welch t-test.
LIVE (kpi_shift 등)현재 교대 누적 → "오늘"을 Oracle 재스캔 없이.
작업풀 (live_workqueue/pool)60초 full-replace.
시간대(필수)

서버는 KST지만 터미널/Oracle은 MYT(UTC+8, Westports). 교대 감지·기간 경계는 반드시 wp_core::shift::terminal_now() 사용(서버 Local::now()를 쓰면 교대 1h 오판·0행). 화면 표시 시각도 터미널 현지(MYT).
