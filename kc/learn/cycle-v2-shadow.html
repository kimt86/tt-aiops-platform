사이클 감지 v2 — 그림자 검증

6-이벤트 사이클 모델의 그림자(병렬) 검증 — v2.2→v2.6 반복과 게이트.

러닝 · 실험역사 기록 · 2026-06-12
갱신 — 현행은 별도 문서

현행 사이클 분해(5단계로 축소·데이터 소스·2단계 TOS 보정)는 TT 사이클 분해 — 현행으로 이관됐습니다. 아래 "외부 정답지 없음"은 정정: 이후 크레인 작업 로그(rtg_move_log·qc_move_log)로 핸드오버 정답지가 생겼습니다(단 트럭 사건은 상차=픽업의 comp_ts만). 아래는 2026-06-12 시점 실험 기록으로 보존.

가설

레그(leg, topos1 타깃 단위) 기반 차세대 사이클 감지(v2)가 현행 이동필터(v1)보다 사이클 경계와 trip별 도착을 더 정확하게 잡을 수 있다. v1 핫패스는 건드리지 않고 그림자(병렬)로 tt_cycle_v2에 적재해 같은 행(ytno+dropped_at)으로 페어드 비교.

수집 우선순위: ① 사이클 열림/닫힘 시각(최우선) → ② 각 trip 시작·도착 위치+시각 → ③ 크레인 핸드오버 시작/종료(있으면 좋고 없으면 뺌).

방법 — 비교·게이트 규칙

  • 페어드 비교: 같은 (ytno, dropped_at)에서 v1 vs v2(운영 변동이 양쪽에 동일 작용).
  • 워밍업 필터: 재시작 직후 ~15분 내 완료 사이클은 앞 단계 누락 → opened_at > 재시작+15분만 평가.

핵심 발견 (확정)

  • 크레인(QC) 도착은 GPS로 못 잡는다 — QC GPS가 디바이스맵에 유효 진입하지 않아 arrived가 거의 0. 약경계의 근본 원인.
  • 그래서 크레인 도착은 cur_loc=WHARF의 ~200초 조기 latch를 이후 ARRIVED로 업그레이드해서 얻음(Fix A). |Δ| 200초→1초.
  • 닫힘 dropped_at = container1 클리어(≈인계 종료 + TOS 갱신, 드롭 도착 후 중앙 ~5.5분) — 물리적 들어올림 순간이 아님.
  • v2는 거짓 분할 억제로 경계가 v1보다 정확: 2분 미만 비정상 사이클 v1 7.5% → v2 0.9%, 중앙 길이 14→17.6분.

6-이벤트 모델 (현재)

핸드오버 시작 시각은 웹소켓으로 신뢰도 있게 관측 불가(QC PLC에 트럭 식별자 없음) → 수집 포기. 받기·주기는 체류 간격으로 대체.
