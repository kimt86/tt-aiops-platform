학습 센터 기획 (Learning Center)

학습 센터는 누적되는 작업 사이클 데이터로 예측 모형을 학습→검증→활용하는 일을 한곳에서 굴리는 거점입니다. 무엇을·어떻게의 기술 상세는 예측 모형 연구에 있고, 이 문서는 그 학습을 어떻게 조직·운영·활용할지의 프로그램 차터입니다.

확정 스펙이 아니라 학습 센터를 어떻게 굴릴지의 출발점. 목표 지표·범위·합의 항목은 함께 검토해 고칩니다.

  • 이미 tt_cycle_v2(6-이벤트)를 검증된 단위로 쌓고 있다 — 학습 연료가 매일 쌓인다.
  • 흩어지면 또 까먹는다. 데이터셋·모델·실험·교훈을 지식센터 컨벤션 위에 단일 출처로 모은다.

1. 무엇을 학습할지

1차 범위 — 웹소켓(GPS) 데이터만으로 학습할 3가지(확정):

#학습 대상출력웹소켓 원천
①TT 이동시간(실측 OD)순수주행 = 구간(출발→작업지점 도달) 소요 초GPS 트립(6-이벤트)
②블록 작업지점 좌표각 topos 코드의 실제 (x,y)GPS 좌표 ↔ topos1 누적
③차량 주행 차선·방향실제 다니는 도로·차선 네트워크(경로·방향)GPS 트레이스 집계

②③ = 레이아웃을 데이터로 학습. 세 가지가 맞물린다: ②로 출발·도착 지점을 찍고, ③ 차선망 위 경로로 거리를 잡아, ①(이동시간)을 레이아웃 인지로 끌어올린다.

순수주행 라벨 — 구간시간

①의 학습 라벨은 순수주행 = 주행 구간 시간(출발→작업지점 도달; 경로 정체 포함·핸드오버 대기 제외). ARRIVED가 실제 도착과 거의 같아(중앙 −4초) 큰 크레인 대기는 이동시간 밖(도착 이후). 같은 OD에서도 CV 0.758로 대기 노이즈가 지배해 거리 모델 정확도 바닥이 여기서 정해짐. [2026-07-01] 한때 "움직인 순간만(drive_s)"으로 뒀으나 경로 정체까지 벗겨 틀렸으므로 구간시간으로 교정. 비용원 learn_travel_sample 빈트립(mig 0080). learn_leg_decomp는 retire(mig 0081). → 이동시간 모델.

연구의 다른 예측기(QC ETW·블록 핸드오버·곧유휴)는 PLC·TOS DB가 함께 필요해 1차 범위 밖. 데이터·합의가 갖춰진 뒤 확장.

2. 어떻게 학습할지

  • 자가 라벨(record-only): 운영 중 파이프라인으로 예측 vs 실제를 매 배차 기록 → 라벨 자동 누적. 별도 라벨링 없음.
  • 점진적 복잡도: v0 베이스라인(구간별 중앙값) → v1 그래디언트 부스팅 → 필요 시 v2. 항상 v0 대비 개선분 입증.
  • 정직한 검증: 시간 분할(미래 교대로 검증·누설 차단), MAE(초)·P90, 주/야·물량·작업종류 층화.
  • 데이터 품질 규율: 관측 못 한 값은 NULL(추측 금지) · 세 신호(GPS·PLC·TOS) 교차 일치 표본만 · 누설 방지(피처는 t₀ 이전만).

3. 학습한 것을 어떻게 활용할지

  • 배차 비용 함수에 투입: ①(이동시간) + ②③(레이아웃)으로 후보 도착비용 산출 → 최소비용 매칭 기본 비용(= free_in + 이동시간). 현재 이동비용 = ③의 도로망 위 길찾기 시간 × ①의 실측 보정(2026-07-02~): 작업지점이 전부 커넥터로 도로에 연결돼 거의 모든 쌍 계산, 라우팅 불능만 quay_manhattan_m ÷ 3.30 m/s 폴백. 225m 격자 조회 폐기(mig 0082).
  • 크레인 앞 대기는 이동비용에서 제외: 도착 후 대기는 도착 이후(크레인 스케줄) 영역. [2026-07-01 정정] "크레인별 진입 대기"(learn_crane_approach)를 1단계에 넣으려 했으나 재보니 거의 0(옛 67초는 편향)이라 폐기.
  • 그림자 → 측정 → 승격(사이클 v2와 같은 규율): record-only로 예측·추천을 그림자로 돌려 lift 측정, 게이트 통과 시에만 실제 배차 반영.
  • 폴백 안전: 예측 신뢰 낮음·모형 장애 시 1단계 거리비용으로 즉시 복귀. 2단계는 1단계 위에 얹는 가중치라 투자가 보호됨.

4. 레이아웃(②③) 학습 — 방법·활용

  • ② 블록 작업지점 좌표: 트럭이 topos1 타깃에 도착(ARRIVED)한 순간들의 GPS 좌표를 코드별로 누적·클러스터링 → 대표 (x,y). 6-이벤트 도착 표본이 깨끗.
  • ③ 차량 주행 차선: 전체 GPS 트레이스를 도로·차선 네트워크로 추론(빈번 경로·방향·차선 수). GPS는 ~3초로 성기므로 차선 단위는 정확도 임계(≤30m)에서만 채택.
  • 활용: ②③ → 데이터로 구성한 레이아웃 → ①의 이동시간이 이 도로망 위 길찾기로 계산(2026-07-02~ 배차 비용의 본체). 도로망은 매시 Python cron이 GPS→스켈레톤→링크로 추론(7,189노드·작업지점 5,888 커넥터·방향 다수결), Rust 방향 Dijkstra.
도로망 라우팅 — 첫 게이트 탈락 → 재구축해 배차 비용에 채택 (2026-07-02)

첫 판은 작업지점이 도로에서 중앙 52m·30%만 계산·상관 맨해튼보다 낮아 탈락. 재구축(전부 커넥터·조밀화·방향 다수결 — 성공률 46.6→96.7%) 후 비용 = 경로시간 → 실측 "실제시간 곡선"으로 채택, 격자 룩업 폐기. 정확도는 맨해튼과 대등(격자형)이나 천장+일반화가 채택 근거. road_route_eval 상시 게이트. → 이동시간 모델.

6. 단계별 로드맵

  1. 지금: record-only 파이프라인 가동, train_* 테이블 축적, v0 베이스라인으로 데이터 건전성 조기 점검.

  3. 전환 검증: record-only로 예측 vs 실제 lift 공동 판정.

원칙

  • 그림자 → 검증 → 승격. 검증 안 된 예측을 핫패스에 바로 쓰지 않는다.
  • 관측 못 한 값은 NULL, 추측 금지. 베이스라인 먼저, 복잡도는 입증된 만큼만.
  • 모든 학습 문서는 글쓰기 규칙의 상태표시·(미검증) 원칙을 따른다.
