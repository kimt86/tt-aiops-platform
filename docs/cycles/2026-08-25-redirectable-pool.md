# 재지향 가능 공차 판별 — 선행 측정과 배선 (pool_ver 8)

2026-08-25. 사용자 결정: "배차 할당 후에도 스왑 가능한 공차를 후보 트럭 풀에 넣는다."
배선 전에 판별 정확도를 소급 측정으로 확정했다(HANDOFF 중단 규칙: 오판율이 크면 배선 전 멈춤).

## ① Q 라벨 오판율 — 원측정과 반전

**분모**: 최근 24시간 `assigned_tt_hist`(매 틱 배차 목록 스냅샷)의 jobstatus='Q' 트럭-틱 125,772개.
**정답지**: `tt_move_log` 사이클 구간(pickup_ts ≤ t < free_ts 면 "적재 중"·픽업/자유 100% 채움).

- Q 트럭-틱의 **7.70%**(9,679)가 실제로는 적재 중이었다.
- 그런데 오판 틱의 픽업 후 경과가 p50 569초·p90 1,956초 — 추출 지연(≤120초)으로 설명되는 건
  1,361개(전체의 1.1%)뿐이다. 반면 Q→A 전환 지연은 픽업 후 p50 35~42초로 빠르다(아래 ②).
- **해석(측정과 분리)**: 이 7.7%는 라벨 오류가 아니라 **선배정**이다 — TOS 는 트럭이 상자를
  싣고 달리는 중에도 다음 작업을 미리 Q 로 배정한다. 그 Q행은 진짜(다음 작업 픽업 전)지만
  트럭은 공차가 아니다. 라이브 확인: Q트럭 70대 중 25대가 같은 순간 A행(픽업된 현재 작업)도
  보유 — "같은 트럭의 A행 없음" 조건이 이 부류를 거른다.

⇒ **판별 규칙(배선된 것)**: Q+트럭 행 ∧ 같은 트럭 A행 없음 ∧ 픽업 로그 가드(마지막 픽업 ≤ 마지막
자유) ∧ 픽업 지점 500m(SWAP_MIN_M·표시와 동일 임계) 밖. 잔여 오판 = 미러 지연 창 **~1.1%** → 게이트 통과.

## ③ 배선 (커밋 참조)

- 풀 갈래 `reason='redirectable'`(POOL_VER 8) · truck_n(슬롯 수)에 불산입 — 발행량 불변.
- 행렬: 재지향 트럭 간선 = 이동시간 + `REDIRECT_PENALTY_S`(180초). 자기 작업은 tos_assigned 라
  행렬에 없으므로 이 트럭의 모든 간선이 재지향이다.
- 추천 표식 `stage2_match_shadow.redirected_from`(mig0160) · 보드 "재지향" 칩.
- 예상: 트럭 잉여 체제(held 188~228)에선 재지향 추천이 드물다 — 0이어도 배선 실패가 아니라
  벌점이 제 일을 하는 것. 실효는 다음 사이클(전 작업 후보 확장)과 결합할 때 커진다.
